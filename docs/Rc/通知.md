# 站内通知

## 说明

- 路由前缀：`/rc`
- 鉴权：均需 `Bearer Token`，并使用 `auth:rc`
- 成功响应：`api_response()`，结构为 `code` + `data` + `meta`
- 业务错误：`error()`，结构为 `code` + `message` + `meta`

> 通知与投递流程联动，详见 [投递.md](./投递.md)。通知由服务端自动写入，**无手动创建接口**。

### 数据范围

- 通知按**用户**（`user_id`）隔离，并按 Token 当前绑定的**身份**（`user_identity_id`）过滤可见范围
- 列表、未读数、已读操作仅作用于「当前身份可见」的通知
- **身份级通知**：`user_identity_id` 有值，仅在该 `UserIdentity` 下可见（如求职者面试邀请）
- **用户级通知**：`user_identity_id` 为 `null`，当前用户任意身份下均可见
- 通知粒度到身份一级；若需通知同组织多人，应对每个人/身份分别写入
- 当前由投递流程自动写入的通知均绑定候选人的**求职者** `user_identity_id`

### 列表公共规则

- 列表按事件发生时间倒序（`happened_at DESC -> id DESC`）
- 分页结构与 Laravel 标准分页一致：`data`、`total`、`per_page`、`current_page`、`last_page` 等
- Query 参数 `per_page`：默认 15，最大 100

### 响应 `meta` 结构（成功）

| 字段 | 类型 | 说明 |
|------|------|------|
| `timestamp` | float | 服务端时间戳 |
| `response_time` | float | 请求耗时（秒） |

### 响应 `meta` 结构（业务错误）

| 字段 | 类型 | 说明 |
|------|------|------|
| `timestamp` | float | 服务端时间戳 |
| `response_time` | float | 请求耗时（秒） |

## 公共数据结构

### 通知对象（`RcNotificationResource`）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | int | 通知 ID |
| `user_identity_id` | int\|null | 接收身份 ID；用户级通知为 `null` |
| `user_identity_type` | int\|null | 接收身份类型（由 `user_identity_id` 关联得出，非表字段），见 [RcIdentityType](./认证.md) |
| `user_identity_type_label` | string\|null | 接收身份类型中文（关联得出） |
| `type` | int | 通知类型，见 [RcNotificationType](#rcnotificationtype) |
| `type_label` | string\|null | 通知类型中文 |
| `title` | string | 通知标题 |
| `body` | string\|null | 通知摘要 |
| `payload` | object\|null | 业务扩展数据，用于前端跳转 |
| `is_read` | bool | 是否已读 |
| `read_at` | string\|null | 已读时间 |
| `happened_at` | string\|null | 事件发生时间 |
| `created_at` | string\|null | 创建时间 |

### `payload` 字段说明

`payload` 为 JSON 对象，按通知类型携带不同字段，前端可据此跳转到投递详情等页面。

| 字段 | 类型 | 出现场景 | 说明 |
|------|------|----------|------|
| `application_id` | int | 全部 | 投递记录 ID，可跳转 `GET /rc/applications/{id}` |
| `job_id` | int | 全部 | 职位 ID |
| `company_id` | int | 全部 | 企业 ID |
| `interview_id` | int | 面试邀请 | 面试记录 ID |
| `status` | int | 投递状态变更 | 变更后的投递状态，见 [RcApplicationStatus](./投递.md#rcapplicationstatus) |
| `activity_id` | int | 校招活动通知 | 活动 ID，可跳转 `GET /rc/companies/school-activities/{id}` |
| `school_activity_company_id` | int | 校招活动通知 | 活动企业报名记录 ID |
| `activity_booth_id` | int\|null | 校招活动通知 | 分配的活动展位 ID |
| `join_source` | int | 校招活动通知 | 报名来源，见 [RcSchoolActivityJoinSource](./校招活动.md#rcschoolactivityjoinsource) |
| `apply_status` | int | 校招活动通知 | 报名状态，见 [RcSchoolActivityApplyStatus](./校招活动.md#rcschoolactivityapplystatus) |

### 按类型的 `payload` 示例

**面试邀请（`type = 1`）**

```json
{
  "application_id": 18,
  "job_id": 12,
  "company_id": 1,
  "interview_id": 5
}
```

**Offer 通知（`type = 2`）**

```json
{
  "application_id": 18,
  "job_id": 12,
  "company_id": 1
}
```

**投递状态变更（`type = 3`）**

```json
{
  "application_id": 18,
  "job_id": 12,
  "company_id": 1,
  "status": 5
}
```

**校招活动邀约（`type = 8`）**

```json
{
  "activity_id": 12,
  "company_id": 1,
  "school_activity_company_id": 88,
  "activity_booth_id": 101,
  "join_source": 0,
  "apply_status": 1
}
```

**校招活动审批通过（`type = 9`）**

```json
{
  "activity_id": 12,
  "company_id": 1,
  "school_activity_company_id": 88,
  "activity_booth_id": null,
  "join_source": 1,
  "apply_status": 1
}
```

## 自动触发规则

| 触发动作 | 接口 | 通知类型 | 接收人 | `title` | `body` 示例 |
|----------|------|----------|--------|---------|-------------|
| 招聘方邀请面试 | `POST /rc/companies/applications/{id}/invite-interview` | `InterviewInvitation` | 求职者 | 面试邀请 | 南昌示例科技有限公司邀请您参加「Laravel 工程师」的面试 |
| 求职者接受面试邀请 | `POST /rc/applications/{id}/accept-interview` | `InterviewInvitationAccepted` | 招聘方（本企业） | 面试邀请已接受 | 求职者甲已接受「Laravel 工程师」的面试邀请 |
| 求职者拒绝面试邀请 | `POST /rc/applications/{id}/reject-interview` | `InterviewInvitationRejected` | 招聘方（本企业） | 面试邀请已拒绝 | 求职者甲已拒绝「Laravel 工程师」的面试邀请 |
| 招聘方发送 Offer | `POST /rc/companies/applications/{id}/send-offer` | `OfferSent` | 求职者 | Offer 通知 | 南昌示例科技有限公司已向您的「Laravel 工程师」投递发送 Offer |
| 求职者接受 Offer | `POST /rc/applications/{id}/accept-offer` | `OfferAcceptedByCandidate` | 招聘方（本企业） | Offer已接受 | 求职者甲已接受「Laravel 工程师」的 Offer |
| 求职者拒绝 Offer | `POST /rc/applications/{id}/reject-offer` | `OfferRejectedByCandidate` | 招聘方（本企业） | Offer已拒绝 | 求职者甲已拒绝「Laravel 工程师」的 Offer |
| 招聘方确认录用 | `POST /rc/companies/applications/{id}/hire` | `ApplicationStatusChanged` | 求职者 | 投递状态变更 | 恭喜！南昌示例科技有限公司 已录用您应聘的「Laravel 工程师」 |
| 招聘方淘汰 | `POST /rc/companies/applications/{id}/reject` | `ApplicationStatusChanged` | 求职者 | 投递状态变更 | 您的「Laravel 工程师」投递已被 南昌示例科技有限公司 淘汰 |
| 院校邀约企业参加活动 | `POST /rc/schools/activities/{activityId}/company-invitations` | `SchoolActivityCompanyInvited` | 招聘方（本企业全部绑定用户） | 校招活动邀约 | 北京大学邀请贵司参加「2026 春季双选会」 |
| 院校审批通过企业申请 | `POST /rc/schools/activities/{activityId}/company-applications/{id}/approve` | `SchoolActivityCompanyApproved` | 招聘方（本企业全部绑定用户） | 校招活动审批通过 | 北京大学已通过贵司参加「2026 春季双选会」的申请 |

## 1) 通知列表

- 接口：`GET /rc/notifications`

### Query 参数

| 字段 | 是否必填 | 说明 |
|------|----------|------|
| `is_read` | 否 | 按已读状态筛选：`0` / `false` 未读，`1` / `true` 已读 |
| `type` | 否 | 按通知类型筛选，见 [RcNotificationType](#rcnotificationtype) |
| `per_page` | 否 | 每页条数，默认 15，最大 100 |

```http
GET /rc/notifications?is_read=0&per_page=15
Authorization: Bearer {token}
```

### 身份隔离说明

同一用户同时拥有求职者与招聘方身份时，以 Token 当前身份过滤：

| 当前身份 | 可见通知 |
|----------|----------|
| 求职者（`user_identity_id = 3`） | `user_identity_id = 3` 的身份级通知 + 用户级通知 |
| 招聘方（`user_identity_id = 8`） | `user_identity_id = 8` 的身份级通知 + 用户级通知；**看不到** `user_identity_id = 3` 的求职者通知 |

## 5) 全部标记已读

- 接口：`POST /rc/notifications/read-all`
- 描述：将当前用户在**当前 Token 身份**下可见的所有未读通知批量标记为已读

### 请求示例

```http
POST /rc/notifications/read-all
Authorization: Bearer {token}
Content-Type: application/json
```

### 成功响应示例

```json
{
  "code": 200,
  "data": {
    "updated_count": 3,
    "unread_count": 0
  },
  "meta": {
    "timestamp": 1749732600.123456,
    "response_time": 0.022
  }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `updated_count` | int | 本次实际更新的未读条数 |
| `unread_count` | int | 更新后的未读数量，固定为 `0` |

### 无可更新时

```json
{
  "code": 200,
  "data": {
    "updated_count": 0,
    "unread_count": 0
  },
  "meta": {
    "timestamp": 1749732600.123456,
    "response_time": 0.008
  }
}
```

## 前端推荐流程

### 求职者

1. 进入应用时拉取未读数 `GET /rc/notifications/unread-count`，展示角标
2. 打开通知中心 `GET /rc/notifications`，可按 `is_read=0` 筛选未读
3. 点击通知：
   - 方式一：调用 `GET /rc/notifications/{id}` 查看详情并自动已读
   - 方式二：调用 `POST /rc/notifications/{id}/read` 标记已读后，根据 `payload.application_id` 跳转投递详情
4. 支持一键清空未读 `POST /rc/notifications/read-all`

### 招聘方

1. 进入应用时拉取未读数 `GET /rc/notifications/unread-count`（需切换招聘方身份）
2. 候选人接受 / 拒绝面试邀请、接受 / 拒绝 Offer 时会收到对应通知
3. 根据 `payload.application_id` 跳转投递详情处理后续流程（发 Offer、确认录用等）

### 跳转建议

| `type` | 建议跳转 |
|--------|----------|
| `InterviewInvitation` | 投递详情 `GET /rc/applications/{payload.application_id}`，可展示 `pending_interview_invitation` 并引导接受 / 拒绝 |
| `OfferSent` | 投递详情 `GET /rc/applications/{payload.application_id}` |
| `ApplicationStatusChanged` | 投递详情 `GET /rc/applications/{payload.application_id}` |
| `InterviewInvitationAccepted` | 投递详情 `GET /rc/applications/{payload.application_id}` |
| `InterviewInvitationRejected` | 投递详情 `GET /rc/applications/{payload.application_id}` |
| `OfferAcceptedByCandidate` | 投递详情 `GET /rc/applications/{payload.application_id}`，可引导确认录用 |
| `OfferRejectedByCandidate` | 投递详情 `GET /rc/applications/{payload.application_id}`，可重新发送 Offer |

## 枚举

### RcNotificationType

| 值 | 标签 | 说明 |
|----|------|------|
| `1` | 面试邀请 | 招聘方发出面试邀请，待求职者确认 |
| `2` | Offer通知 | 招聘方发送 Offer |
| `3` | 投递状态变更 | 录用、淘汰等状态变更 |
| `4` | 面试邀请已接受 | 求职者接受面试邀请 |
| `5` | 面试邀请已拒绝 | 求职者拒绝面试邀请 |
| `6` | Offer已接受 | 求职者接受 Offer |
| `7` | Offer已拒绝 | 求职者拒绝 Offer |
| `8` | 校招活动邀约 | 院校邀约企业参加活动 |
| `9` | 校招活动审批通过 | 院校通过企业自主申请 |

## 业务失败（通用）

| 场景 | `code` | `message` |
|------|--------|-----------|
| 通知不存在或当前身份不可见 | `404` | 通知不存在。 |
| Token 无效或过期 | `401` | 由 `auth:rc` 中间件返回 |
