# 认证

## 说明

- 路由前缀：`/rc`
- 已注册认证接口：
  - `POST /rc/auth/send-verification-code`（无需鉴权）
  - `POST /rc/auth/phone-login`（无需鉴权）
  - `POST /rc/auth/email-login`（无需鉴权）
  - `POST /rc/auth/forgot-password`（无需鉴权）
  - `POST /rc/auth/wechat-mini-login`（无需鉴权）
  - `POST /rc/auth/wechat-app-login`（无需鉴权）
  - `POST /rc/auth/wechat-bind-phone`（无需鉴权）
  - `GET /rc/auth/me`（需 Bearer Token，`auth:rc`）
  - `GET /rc/auth/organizations`（需 Bearer Token，`auth:rc`）
  - `POST /rc/auth/logout`（需 Bearer Token，`auth:rc`）
  - `POST /rc/auth/refresh-token`（需 Bearer Token，`auth:rc`）
- 返回格式：
  - 成功：`api_response()`，结构为 `code` + `data` + `meta`
  - 业务错误：`error()`，结构为 `code` + `message` + `meta`

---

## 公共数据结构

### 用户对象（登录 / 刷新令牌 / `GET /auth/me` 中的 `user`）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | int | 用户 ID |
| `uuid` | string | 用户 UUID |
| `name` | string\|null | 姓名 |
| `nickname` | string\|null | 昵称 |
| `phone` | string\|null | 手机号 |
| `email` | string\|null | 邮箱 |
| `gender` | int | 性别 |
| `avatar` | string\|null | 头像 |
| `last_login_ip` | string\|null | 最近登录 IP |
| `last_login_at` | string\|null | 最近登录时间 |
| `current_identity` | object\|null | 当前 Token 关联的身份，结构见 [用户身份对象](#用户身份对象-useridentity) |
| `identities` | array | 全部身份列表，按 `is_default DESC, id ASC` |

### 用户身份对象（UserIdentity）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | int | 身份 ID（Token `responsible_id` 指向此字段） |
| `user_id` | int | 所属用户 ID |
| `organization_type` | string\|null | 所属机构多态类型：`company` / `school` / `area`；未绑定时为 `null` |
| `organization_id` | int\|null | 所属机构 ID；未绑定时为 `null` |
| `organization` | object\|null | **关联机构详情**（`organization_id` 有值且能解析时返回；否则为 `null`） |
| `identity_type` | int | 身份类型，见 [identity_type 枚举](#identity_type-枚举) |
| `identity_name` | string | 身份名称 |
| `organization_name` | string\|null | 所属机构名称（冗余展示字段） |
| `job_title` | string\|null | 在该机构下的岗位/头衔 |
| `is_default` | int | 是否默认身份（`1` = 是，`0` = 否） |
| `status` | int | 身份状态（`1` = 启用，`0` = 停用） |
| `extra` | object\|null | 扩展字段 |
| `has_basic_info` | bool | 是否已完成该身份基础信息 |
| `created_at` | string\|null | 创建时间 |
| `updated_at` | string\|null | 更新时间 |

#### `organization` 对象说明

- 由身份上的 `organization_type` + `organization_id` 多态关联加载，**与** `organization_type` / `organization_id` **同时返回**（便于前端直接展示，无需再请求机构详情）。
- 登录、`/auth/me`、刷新令牌时，对 `identities` 及 `current_identity` 均会预加载 `organization`。
- 认证接口中的 `organization` **不包含**企业下的 `licenses`、`contacts`（仅主体字段）；完整企业资料见 [`GET /rc/companies/lookup`](./企业.md)。

| `organization_type` | `organization` 对象类型 | 主要字段 |
|----------------------|-------------------------|----------|
| `company` | 企业（`Company`） | `id`, `parent_id`, `depth`, `name`, `credit_code`, `legal_person`, `contact_phone`, `address`, `status`, `created_at`, `updated_at` |
| `school` | 学校（`School`） | `id`, `name`, `code`, `parent_code`, `level`, `type`, `created_at`, `updated_at` |
| `area` | 行政区划（`Area`） | `id`, `name`, `code`, `parent_code`, `level`, `type`, `created_at`, `updated_at` |

`has_basic_info` 判定（招聘方 / 校招 / 政府）：`organization_id` 不为空即为 `true`。求职者看是否已有简历；猎头恒为 `true`。

#### identity_type 枚举

| 值 | 含义 |
|----|------|
| `1` | 求职者 |
| `2` | 招聘方 |
| `3` | 校招负责人 |
| `4` | 政府机构负责人 |
| `5` | 猎头 |

### 登录/刷新令牌成功响应 `data` 结构

```json
{
  "token_type": "Bearer",
  "access_token": "<access-token>",
  "user": { }
}
```

- `user` 结构见上表。
- `current_identity`：当前 Token 绑定的身份；首次登录且无默认身份时为 `null`。
- 若用户已绑定企业，招聘方身份的 `organization` 为企业对象，见下方示例。

## 1) 发送验证码

- 接口：`POST /rc/auth/send-verification-code`
- 描述：发送登录/找回密码验证码

### 请求参数

```json
{
  "type": "phone",
  "account": "13800138000",
  "scene": "login"
}
```

### 字段规则

- `type`：必填，`phone` 或 `email`
- `account`：必填，字符串，最大 100
- `scene`：必填，`login`、`bind` 或 `forgot_password`
- App 微信绑定手机号时使用 `type=phone`、`scene=bind`

### 成功响应示例

```json
{
  "code": 200,
  "data": [],
  "meta": {
    "timestamp": 1748500000.1234,
    "response_time": 0.0123
  }
}
```

### 业务失败响应示例（发送频率限制）

```json
{
  "code": 429,
  "message": "发送过于频繁，请稍后再试。",
  "meta": {
    "timestamp": 1748500000.1234,
    "response_time": 0.0123,
    "expires_in": 55
  }
}
```

> `meta.expires_in`：剩余冷却秒数。

## 3) 邮箱登录

- 接口：`POST /rc/auth/email-login`
- 描述：验证码登录；若用户不存在会自动注册

### 请求参数

```json
{
  "email": "test@example.com",
  "code": "123456"
}
```

### 字段规则

- `email`：必填，合法邮箱（RFC + DNS 校验），最大 100；服务端会统一转小写
- `code`：必填，6 位数字

### 成功响应

- 结构同「手机号登录」；`user` 中含 `current_identity`、`identities`，且每项可含 `organization`。

### 业务失败响应

- 验证码错误或失效：同「手机号登录」失败响应。

## 4) 忘记密码

- 接口：`POST /rc/auth/forgot-password`
- 描述：验证码校验后重置密码

### 请求参数

```json
{
  "type": "email",
  "account": "test@example.com",
  "code": "123456",
  "password": "new-password",
  "password_confirmation": "new-password"
}
```

### 字段规则

- `type`：必填，`phone` 或 `email`
- `account`：必填，字符串，最大 100
- `code`：必填，6 位数字
- `password`：必填，需满足 Laravel 默认密码强度规则，且需通过 `password_confirmation` 确认
- `password_confirmation`：必填，必须与 `password` 一致

### 成功响应示例

```json
{
  "code": 200,
  "data": [],
  "meta": {
    "timestamp": 1748500000.1234,
    "response_time": 0.0123
  }
}
```

### 业务失败响应示例

- 验证码错误或失效：

```json
{
  "code": 422,
  "message": "验证码错误或已失效。",
  "meta": {
    "timestamp": 1748500000.1234,
    "response_time": 0.0123
  }
}
```

- 用户不存在：

{
  "code": 422,

## 5.1) 获取当前身份下全部机构

- 接口：`GET /rc/auth/organizations`
- 鉴权：Bearer Token（`auth:rc`）
- 描述：根据 **当前 Token 关联身份** 的 `identity_type`，返回该用户在此身份类型下、状态为启用且已绑定机构的所有记录（含机构详情）。例如招聘方身份返回全部已绑定企业，校招负责人返回全部已绑定学校，政府机构负责人返回全部已绑定行政区划。
- 前提：Token 须已通过 `POST /rc/auth/refresh-token` 等方式绑定 `responsible`（`UserIdentity`）；否则返回业务错误。

### 响应字段（`data`）

| 字段 | 类型 | 说明 |
|------|------|------|
| `identity_type` | int | 当前身份类型，见 [identity_type 枚举](#identity_type-枚举) |
| `identity_type_label` | string\|null | 身份类型中文名 |
| `organization_type` | string\|null | 机构多态类型：`company` / `school` / `area`；求职者、猎头等无固定机构类型时为 `null` |
| `items` | array | 绑定列表，按 `is_default DESC, id ASC` 排序 |

#### `items[]` 元素

| 字段 | 类型 | 说明 |
|------|------|------|
| `identity_id` | int | 身份记录 ID（`rc_user_identities.id`） |
| `identity_name` | string | 身份名称 |
| `organization_type` | string | 机构多态类型 |
| `organization_id` | int | 机构 ID |
| `organization_name` | string\|null | 机构名称（冗余） |
| `job_title` | string\|null | 在该机构下的岗位/头衔 |
| `is_default` | int | 是否默认身份行 |
| `status` | int | 身份状态（`1` 启用） |
| `organization` | object\|null | 机构详情，结构同 [organization 对象说明](#organization-对象说明) |

## 7) 切换/绑定身份（刷新令牌）

- 接口：`POST /rc/auth/refresh-token`
- 鉴权：Bearer Token（`auth:rc`）
- 描述：切换默认身份并颁发新 Token，撤销旧 Token。支持两种入参方式（二选一）：
  - **`identity_id`**（推荐）：切换到用户已有的某条身份记录（如多家企业的招聘方、多所学校等场景）；须为当前用户名下且状态为启用的身份。
  - **`identity_type`**：按身份类型切换；若该类型下尚无任何记录则自动创建（此时 `organization` 为 `null`）。同一 `identity_type` 存在多条记录时，会匹配**最早创建**的那条。

### 请求参数（按身份 ID 切换）

```json
{
  "identity_id": 11
}
```

### 请求参数（按身份类型切换 / 自动创建）

```json
{
  "identity_type": 2
}
```

### 字段规则

- `identity_id` 与 `identity_type` **二选一**，不可同时省略。
- `identity_id`：整数，须为当前用户 `rc_user_identities.id`。
- `identity_type`：整数，见 [identity_type 枚举](#identity_type-枚举)。

### 业务错误

| HTTP | `code` | `message` | 说明 |
|------|--------|-----------|------|
| 200 | 422 | 该身份已停用。 | `identity_id` 对应身份 `status = 0` |
| 200 | 422 | — | 参数校验失败（未传参、`identity_id` 不存在或不属于当前用户、`identity_type` 非法等），`message` 为 Laravel 校验文案 |

## 8) 微信小程序登录

- 接口：`POST /rc/auth/wechat-mini-login`
- 鉴权：无需鉴权
- 流程：后端用 `code` 调用 `auth.code2Session`，再用 `phone_code` 调用 `phonenumber.getPhoneNumber`
- 账号匹配：优先匹配已有微信 `unionid/openid`，否则按微信已验证手机号匹配或注册

### 请求参数

| 字段 | 是否必填 | 类型/规则 | 说明 |
|------|----------|-----------|------|
| `code` | 是 | string，最大 255 | `wx.login` 返回的临时登录凭证，仅可使用一次 |
| `phone_code` | 是 | string，最大 255 | `getPhoneNumber` 按钮返回的动态凭证 |
| `nickname` | 否 | string\|null，最大 50 | 微信昵称 |
| `avatar` | 否 | string\|null，最大 500 | 长期可访问头像 URL，可先调用 `POST /rc/upload/avatar` |

### 请求示例

```json
{
  "code": "0a3...",
  "phone_code": "24_...",
  "nickname": "微信用户",
  "avatar": "https://cdn.example.com/uploads/rc/avatar/2026/07/30/example.jpg"
}
```

### 成功响应

响应 `data` 与普通登录一致：

```json
{
  "code": 200,
  "data": {
    "token_type": "Bearer",
    "access_token": "<access-token>",
    "user": {
      "id": 1,
      "phone": "13800138000",
      "nickname": "微信用户"
    }
  },
  "meta": {}
}
```

`nickname` 和 `avatar` 只会填充用户尚未设置的资料，不覆盖用户主动维护的资料。

## 9) 微信 App 登录

- 接口：`POST /rc/auth/wechat-app-login`
- 鉴权：无需鉴权
- 流程：后端用授权码调用微信开放平台 OAuth2 接口获取 `openid/unionid`
- 注意：App 微信 SDK 不提供已验证手机号，因此首次登录可能进入手机号绑定流程

### 请求参数

| 字段 | 是否必填 | 类型/规则 | 说明 |
|------|----------|-----------|------|
| `code` | 是 | string，最大 255 | `uni.login({ provider: "weixin", onlyAuthorize: true })` 返回的授权码 |
| `nickname` | 否 | string\|null，最大 50 | 微信资料中的昵称 |
| `avatar` | 否 | string\|null，最大 500 | 微信资料中的头像 URL |

### 已绑定手机号

```json
{
  "code": 200,
  "data": {
    "status": "ok",
    "token_type": "Bearer",
    "access_token": "<access-token>",
    "user": {}
  },
  "meta": {}
}
```

### 尚未绑定手机号

```json
{
  "code": 200,
  "data": {
    "status": "need_phone",
    "pending_token": "<64-character-token>",
    "token_type": null,
    "access_token": null,
    "user": null
  },
  "meta": {}
}
```

`pending_token` 默认有效期为 600 秒，仅用于下一步绑定手机号；成功绑定后立即失效。前端不要将其当作登录令牌，也不要放入 Authorization 请求头。

## 10) 微信 App 绑定手机号

- 接口：`POST /rc/auth/wechat-bind-phone`
- 鉴权：无需鉴权
- 前置步骤：
  1. 从 `wechat-app-login` 获取 `pending_token`
  2. 调用 `POST /rc/auth/send-verification-code`，参数为 `type=phone`、`scene=bind`
  3. 提交手机号与短信验证码

### 发送绑定验证码示例

```json
{
  "type": "phone",
  "account": "13800138000",
  "scene": "bind"
}
```

### 绑定请求

```json
{
  "pending_token": "<64-character-token>",
  "phone": "13800138000",
  "code": "123456"
}
```

| 字段 | 是否必填 | 类型/规则 | 说明 |
|------|----------|-----------|------|
| `pending_token` | 是 | string，固定 64 字符 | App 微信登录返回的待绑定令牌 |
| `phone` | 是 | 中国大陆手机号 | 要绑定的手机号 |
| `code` | 是 | 6 位数字 | `scene=bind` 对应的短信验证码 |

成功响应与普通登录的 `LoginResult` 一致。以下情况返回 HTTP `422`：

- `pending_token` 已过期、无效或已被使用；
- 短信验证码错误或失效；
- 微信身份和手机号已分别绑定到不同用户，后端拒绝自动合并。

## 微信登录错误与配置

### 常见状态码

| HTTP/code | 场景 |
|-----------|------|
| `200` | 登录成功，或 App 登录需要继续绑定手机号 |
| `422` | 请求验证失败、微信凭证无效、绑定状态失效、账号绑定冲突 |
| `429` | 短信验证码发送过于频繁 |
| `502` | 微信接口网络异常或暂时不可用 |

### 环境变量

```dotenv
WECHAT_MINI_APP_ID=
WECHAT_MINI_APP_SECRET=
WECHAT_APP_ID=
WECHAT_APP_SECRET=
WECHAT_PENDING_TOKEN_TTL=600
```

- 小程序与 App 使用不同 AppID/Secret。
- `WECHAT_PENDING_TOKEN_TTL` 单位为秒。
- `pending_token` 保存在应用 Cache 中；多实例部署必须使用共享缓存。
- 微信 `access_token`、App OAuth token 与小程序 `session_key` 不写入数据库。

## 前端使用建议

1. 登录后优先读 `user.current_identity.organization` 展示当前企业/学校/区划信息。
2. 多机构切换：列表用 `GET /rc/auth/organizations`，切换用 `POST /rc/auth/refresh-token` + `identity_id`。
3. `organization_name` 为冗余文案，可与 `organization.name` 互为兜底。
4. 招聘方且 `has_basic_info === false` 时，引导走企业 lookup / 注册 / 绑定流程。
5. 需要证件、股东列表时，调用 `GET /rc/companies/lookup` 或绑定/注册接口返回的完整 `company`（含 `licenses`、`contacts`），不要依赖认证接口中的 `organization`。
6. App 微信登录收到 `status=need_phone` 时，先发送 `scene=bind` 验证码，再调用绑定接口；收到 `status=ok` 时直接保存 `access_token`。
