# 人才搜索（招聘方）

## 说明

- 路由前缀：`/rc`
- 鉴权：均需 `Bearer Token`，并使用 `auth:rc`
- 适用对象：招聘方身份（`identity_type = 2`），且当前 Token 关联身份已绑定企业（`organization_type = company`）
- 成功响应：`api_response()`，结构为 `code` + `data` + `meta`
- 业务错误：`error()`，结构为 `code` + `message` + `meta`
- 搜索引擎：基于 Laravel Scout + Elasticsearch，仅返回 `status = 1`（正常）的简历

### 与求职者简历接口的区别

| 对比项 | `GET /rc/resumes` | `GET /rc/talent/resumes` |
|--------|-------------------|--------------------------|
| 适用身份 | 求职者 | 招聘方（已绑定企业） |
| 数据范围 | 仅当前登录用户自己的简历 | 全平台可搜索的正常简历 |
| 搜索能力 | 无关键词搜索，按主简历/更新时间排序 | 支持全文搜索 + 多条件筛选 |
| 响应序列化 | 分页对象（未强制 Resource 转换） | `RcResumeResource` |

---

## 公共数据结构

### 简历预览对象（`RcResumePreviewResource`）

招聘方在推荐、搜索、详情场景下使用脱敏后的预览对象，**不包含**手机号、邮箱、身份证号、简历附件、全文内容与解析数据、详细住址等私人信息。

列表与详情共用该 Resource；详情额外返回 `works`、`educations`、`intentions` 子集合。

### 列表分页

列表接口 `data` 为 Laravel 分页结构：`data`（条目数组）、`total`、`per_page`、`current_page`、`last_page` 等。

### 与简历推荐接口的区别

| 对比项 | `GET /rc/talent/resumes` | `GET /rc/talent/resumes/recommend` |
|--------|--------------------------|--------------------------------------|
| 筛选来源 | 用户主动传 Query 参数 | 系统按策略推导筛选条件 |
| 响应额外字段 | 无 | `data.recommendation`（策略与已应用筛选） |

## 1) 推荐候选人简历

- 接口：`GET /rc/talent/resumes/recommend`
- 描述：招聘方按推荐策略返回候选人简历，按 `updated_at` 倒序
- 鉴权：需 `Bearer Token`（`auth:rc`），且为已绑定企业的招聘方身份

### 推荐策略

| 策略 | 触发条件 | 筛选规则 |
|------|----------|----------|
| `job` | 传 `job_id` 且职位已发布未过期，或未传时取企业最新已发布职位 | 按职位映射：现居城市、学历、工作年限、职位标题关键词 |
| `default` | 企业无可推荐职位时兜底 | 返回全部正常简历，无额外筛选 |

职位映射规则（`job` 策略）：

| 职位字段 | 简历筛选字段 |
|----------|--------------|
| `city_code` | `current_city_code`（仅当前市） |
| `education_level` | `highest_education_level` |
| `experience_min` / `experience_max` | `work_years_min` / `work_years_max` |
| `title` | `keyword`（全文检索） |

### Query 参数

| 字段 | 是否必填 | 说明 |
|------|----------|------|
| `job_id` | 否 | 指定职位 ID；须属于当前绑定企业且已发布 |
| `per_page` | 否 | 每页条数，默认 15，最大 100 |

### 成功响应补充字段

分页结构同搜索接口，额外包含：

| 字段 | 说明 |
|------|------|
| `data.recommendation.strategy` | 本次使用的策略：`job` / `default` |
| `data.recommendation.applied_filters` | 实际传给搜索引擎的筛选条件 |
| `data.recommendation.sort` | 排序字段与方向 |
| `data.recommendation.job_id` | `job` 策略时返回的职位 ID |

### 脱敏字段说明

以下字段在 `GET /rc/talent/resumes`、`GET /rc/talent/resumes/recommend`、`GET /rc/talent/resumes/{id}` 中均不返回：

| 字段 | 说明 |
|------|------|
| `phone` | 手机号 |
| `email` | 邮箱 |
| `id_card` | 身份证号 |
| `file_url` / `display_file_url` / `file_name` / `file_ext` | 简历附件 |
| `text_content` / `parsed_data` | 简历全文与解析数据 |
| `current_residence_detail` / `household_register_detail` | 详细住址 |
| `user_id` | 关联用户 ID |

## 2) 简历详情

- 接口：`GET /rc/talent/resumes/{id}`
- 描述：招聘方查看候选人脱敏简历详情，含工作经历、教育经历、求职意向
- 鉴权：需 `Bearer Token`（`auth:rc`），且为已绑定企业的招聘方身份

### 路径参数

| 字段 | 说明 |
|------|------|
| `id` | 简历 ID |

### 可见规则

仅返回 `status = 1`（正常）的简历；停用或不存在时返回 `404`。

### 成功响应

返回 `RcResumePreviewResource`，并附带：

| 字段 | 说明 |
|------|------|
| `works` | 工作经历列表 |
| `educations` | 教育经历列表 |
| `intentions` | 求职意向列表 |

## 3) 搜索候选人简历

- 接口：`GET /rc/talent/resumes`
- 描述：招聘方按关键词与条件搜索候选人简历，按 `updated_at` 倒序

### Query 参数

| 字段 | 是否必填 | 说明 |
|------|----------|------|
| `keyword` | 否 | 全文搜索关键词；匹配姓名、简历标题、简历编号、工作经历、教育经历、现居城市等 |
| `highest_education_level` | 否 | 最高学历筛选，见 [RcEducationLevel](#rceducationlevel) |
| `current_city_code` | 否 | 现居住城市编码（市级区划 `code`，来源 `GET /rc/meta/areas`） |
| `is_fresh_graduate` | 否 | 是否应届生：`0` 否、`1` 是 |
| `work_years_min` | 否 | 工作年限下限（年，含） |
| `work_years_max` | 否 | 工作年限上限（年，含） |
| `per_page` | 否 | 每页条数，默认 15，最大 100 |

### 关键词匹配范围

`keyword` 会在以下索引字段中检索（由服务端聚合，前端无需传字段名）：

| 分类 | 匹配内容 |
|------|----------|
| 基本信息 | `full_name`、`title`、`resume_no`、`text_content` |
| 工作经历 | 公司名称、职位名称、工作描述 |
| 教育经历 | 学校名称、专业名称 |
| 地址 | `current_residence_city` |

### 请求示例

```http
GET /rc/talent/resumes?keyword=Laravel&highest_education_level=3&work_years_min=3&per_page=15
Authorization: Bearer {token}
```

### 业务错误

| `code` | `message` |
|--------|-----------|
| `422` | 请先切换为招聘方身份并绑定企业。 |

### 规则

- 须先通过 `POST /rc/auth/refresh-token` 切换为招聘方身份，且该身份已绑定企业
- 仅返回 `status = 1`（正常）的简历；停用简历不会出现在搜索结果中
- 不传 `keyword` 时返回所有符合筛选条件的正常简历（按更新时间倒序）
- `work_years_min` 与 `work_years_max` 可组合使用，表示工作年限区间
- 列表项读取 `data.data`；分页信息读取 `data.total`、`data.current_page`、`data.per_page` 等

## 前端推荐流程

1. `POST /rc/auth/refresh-token` 切换招聘方身份（`identity_id` 指向已绑定企业的身份行）
2. 职位详情页：`GET /rc/talent/resumes/recommend?job_id={id}` 推荐匹配候选人
3. 候选人详情：`GET /rc/talent/resumes/{id}` 查看脱敏简历（联系方式需后续付费解锁）
4. 人才首页：`GET /rc/talent/resumes/recommend`（自动取最新已发布职位推导筛选）
5. 主动筛选：`GET /rc/meta/areas` 加载区划树后调用 `GET /rc/talent/resumes`
6. 点击候选人后，可结合投递/人才库等业务接口继续后续流程（待业务模块上线）
