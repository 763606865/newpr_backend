# RC 商品订单与支付

## 1. 说明

本文档描述 RC 招聘业务的商品下单、订单查询、发起支付及支付平台异步通知接口。

客户端接口统一使用 RC Bearer Token：

```http
Authorization: Bearer {rc_access_token}
Content-Type: application/json
```

支付平台通知接口不使用用户 Token，通过微信或支付宝的平台签名验证通知来源。

### 订单有效期

- 待支付订单有效期为 5 分钟。
- 同一付款主体购买同一商品时，如果存在未过期的待支付订单，接口直接返回原订单，不重复创建。
- 复用原订单时，以原订单中的商品数量和金额为准。
- 超过支付期限后，订单会在再次访问时或定时任务执行时被取消。
- 定时任务 `rc:orders:cancel-expired` 每分钟处理一次超时订单。

### 付款主体

| 商品目标端 | `payer_type` | 付款主体 |
|---|---:|---|
| 招聘方 | `1` | 当前招聘方身份绑定的企业 |
| 求职者 | `2` | 当前登录用户 |

## 2. 创建订单

- 接口：`POST /rc/orders`
- 鉴权：RC Bearer Token
- 描述：根据商品套餐创建待支付订单

### 请求参数

| 字段 | 类型 | 必填 | 规则 | 说明 |
|---|---|---|---|---|
| `biz_plan_id` | integer | 是 | 必须是已启用的商品 | `rc_biz_plans.id` |
| `quantity` | integer | 否 | `1`～`999`，默认 `1` | 商品数量 |

### 请求示例

```http
POST /rc/orders
Authorization: Bearer {rc_access_token}
Content-Type: application/json

{
  "biz_plan_id": 12,
  "quantity": 1
}
```

### 业务错误

| `code` | 场景 | `message` 示例 |
|---:|---|---|
| `422` | 商品已下架 | `商品不存在或已下架。` |
| `422` | 招聘方没有绑定企业 | `请先切换到已绑定企业的招聘方身份。` |
| `422` | 商品数量无效 | `商品数量必须大于零。` |

请求字段验证失败时，Laravel 返回 HTTP `422` 验证错误响应。

## 3. 查询订单详情

- 接口：`GET /rc/orders/{id}`
- 鉴权：RC Bearer Token
- 描述：查询当前用户有权访问的订单

用户只能查询本人购买的个人订单，或者本人代表所属企业创建的企业订单。

查询时会检查订单有效期。待支付订单已经超时时，会先自动取消，再返回最新订单状态。

### 请求示例

```http
GET /rc/orders/1001
Authorization: Bearer {rc_access_token}
```

### 成功响应

`data` 直接返回创建订单响应中的 `order` 对象：

```json
{
  "code": 200,
  "data": {
    "id": 1001,
    "order_no": "RC20260728153000A1B2C3D4E5",
    "product_name": "简历刷新卡",
    "payable_amount": "9.90",
    "pay_status": 0,
    "order_status": 0,
    "expired_at": "2026-07-28 15:35:00",
    "items": []
  }
}
```

### 订单不存在或无权访问

```json
{
  "code": 404,
  "message": "订单不存在。",
  "meta": {
    "timestamp": 1785223800.1234,
    "response_time": 0.003
  }
}
```

## 4. 发起支付

- 接口：`POST /rc/orders/{id}/pay`
- 鉴权：RC Bearer Token
- 描述：为有效的待支付订单选择支付渠道并初始化支付流水

### 请求参数

| 字段 | 类型 | 必填 | 可选值 | 说明 |
|---|---|---|---|---|
| `pay_channel` | string | 是 | `wechat`、`alipay` | 支付方式 |
| `pay_scene` | string | 否 | 见下表 | 支付场景；未传时使用 `config/pay.php` 默认值 |
| `openid` | string | 条件必填 | 最大 128 字符 | 微信小程序或公众号支付时必填 |

### 支付场景

| 支付渠道 | `pay_scene` | 说明 |
|---|---|---|
| 微信 | `app` | App 支付 |
| 微信 | `mini` | 微信小程序支付，需要 `openid` |
| 微信 | `mp` | 微信公众号支付，需要 `openid` |
| 微信 | `h5` | 微信 H5 支付 |
| 微信 | `scan` | 微信 Native 扫码支付 |
| 支付宝 | `app` | 支付宝 App 支付 |
| 支付宝 | `h5` | 支付宝手机网站支付 |
| 支付宝 | `web` | 支付宝电脑网站支付 |
| 支付宝 | `scan` | 支付宝扫码支付 |

### 微信支付请求

```http
POST /rc/orders/1001/pay
Authorization: Bearer {rc_access_token}
Content-Type: application/json

{
  "pay_channel": "wechat",
  "pay_scene": "app"
}
```

### 支付宝请求

```json
{

  "pay_scene": "app"
}
```

### 支付流水复用规则

- 同一订单、同一支付渠道存在未过期的初始化支付流水时，返回原支付流水。
- 切换支付渠道时，原渠道的初始化支付流水会被关闭，并创建新支付流水。
- `payment_no` 会作为请求三方支付平台时的商户支付单号 `out_trade_no`。
- `gateway_payload.scene` 表示本次实际使用的支付场景。
- `gateway_payload.payload` 是 Yansongda Pay 返回的拉起支付参数。
- 微信 App、小程序和公众号支付返回客户端 SDK 所需签名参数。
- 微信 H5 返回 `h5_url`，微信扫码支付返回 `code_url`。
- 支付宝 App 返回支付宝订单字符串，H5/网页支付返回支付表单 HTML，扫码支付返回二维码地址。

### 业务错误

| `code` | 场景 | `message` 示例 |
|---:|---|---|
| `404` | 订单不存在或无权访问 | `订单不存在。` |
| `422` | 订单超时 | `订单已超时取消，请重新下单。` |
| `422` | 状态不允许支付 | `当前订单状态不允许支付。` |

## 5. 微信支付异步通知

- 接口：`POST /rc/payments/notify/wechat`
- 鉴权：微信支付 API v3 平台签名
- 调用方：微信支付平台
- 内容类型：`application/json`

该接口不是客户端接口，不应由前端主动调用。

### 必要请求头

| 请求头 | 说明 |
|---|---|
| `Wechatpay-Timestamp` | 微信支付通知时间戳 |
| `Wechatpay-Nonce` | 微信支付通知随机串 |
| `Wechatpay-Signature` | 微信支付平台签名 |
| `Wechatpay-Serial` | 微信支付平台证书或公钥序列号 |

服务端处理流程：

1. 校验请求头是否完整；
2. 由 Yansongda Pay 校验时间戳和平台签名；
3. 由 Yansongda Pay 使用 APIv3 密钥解密 `resource`；
4. 根据解密后的 `out_trade_no` 查询 `rc_payment_transactions.payment_no`；
5. 校验支付渠道、金额和币种；
6. 更新支付流水和订单；
7. 根据订单权益快照发放权益。

### 成功应答

```http
HTTP/1.1 200 OK
Content-Type: application/json

{
  "code": "SUCCESS",
  "message": "成功"
}
```

### 失败应答

```http
HTTP/1.1 400 Bad Request
Content-Type: application/json

{
  "code": "FAIL",
  "message": "失败"
}
```

## 6. 支付宝异步通知

- 接口：`POST /rc/payments/notify/alipay`
- 鉴权：支付宝 RSA2 签名
- 调用方：支付宝
- 内容类型：`application/x-www-form-urlencoded`

该接口不是客户端接口，不应由前端主动调用。

Yansongda Pay 和业务服务会执行以下校验：

- RSA2 签名；
- `app_id`；
- `seller_id`；
- `out_trade_no`；
- 支付渠道；
- `total_amount`；
- 币种。

`TRADE_SUCCESS` 和 `TRADE_FINISHED` 被视为支付成功。其他交易状态会记录为本次支付流水失败，但不会直接关闭仍在五分钟有效期内的订单。

### 成功应答

```http
HTTP/1.1 200 OK
Content-Type: text/plain

success
```

### 失败应答

```http
HTTP/1.1 400 Bad Request
Content-Type: text/plain

failure
```

## 7. 支付成功后的权益处理

支付成功通知会在数据库事务中执行：

1. 将支付流水状态更新为成功；
2. 保存支付平台交易号和原始通知内容；
3. 将订单更新为已支付、已完成；
4. 清空订单的待支付幂等键；
5. 根据订单明细中的 `entitlement_snapshot` 增加权益余额；
6. 写入权益发放流水。

权益流水业务编号格式：

```text
order_paid:{order_id}:{asset_code}
```

支付平台可能重复发送通知。支付流水状态和权益流水业务编号共同保证重复通知不会重复增加权益。

## 8. 枚举

### 支付渠道 `pay_channel`

| 值 | 名称 | 说明 |
|---:|---|---|
| `0` | `Unselected` | 未选择 |
| `1` | `Wechat` | 微信支付 |
| `2` | `Alipay` | 支付宝 |

### 支付状态 `pay_status`

| 值 | 名称 | 说明 |
|---:|---|---|
| `0` | `Pending` | 待支付 |
| `1` | `Paid` | 已支付 |
| `2` | `Failed` | 支付失败 |
| `3` | `Refunded` | 已退款 |

### 订单状态 `order_status`

| 值 | 名称 | 说明 |
|---:|---|---|
| `0` | `PendingPayment` | 待支付 |
| `1` | `Completed` | 已完成 |
| `2` | `Canceled` | 已取消 |
| `3` | `Closed` | 已关闭 |

### 支付流水状态

| 值 | 名称 | 说明 |
|---:|---|---|
| `0` | `Initialized` | 已初始化 |
| `1` | `Succeeded` | 支付成功 |
| `2` | `Failed` | 支付失败 |
| `3` | `Closed` | 已关闭 |

## 9. 支付平台配置

在 `.env` 中配置：

```dotenv
PAY_WECHAT_DEFAULT_SCENE=app
PAY_WECHAT_MCH_ID=
PAY_WECHAT_MCH_SECRET_KEY_V2=
PAY_WECHAT_MCH_SECRET_KEY=
PAY_WECHAT_MCH_SECRET_CERT=
PAY_WECHAT_MCH_PUBLIC_CERT_PATH=
PAY_WECHAT_PUBLIC_CERT_SERIAL=
PAY_WECHAT_PUBLIC_CERT_PATH=
PAY_WECHAT_MP_APP_ID=
PAY_WECHAT_MINI_APP_ID=
PAY_WECHAT_APP_ID=
PAY_WECHAT_MODE=0

PAY_ALIPAY_DEFAULT_SCENE=app
PAY_ALIPAY_APP_ID=
PAY_ALIPAY_SELLER_ID=
PAY_ALIPAY_APP_SECRET_CERT=
PAY_ALIPAY_APP_PUBLIC_CERT_PATH=
PAY_ALIPAY_PUBLIC_CERT_PATH=
PAY_ALIPAY_ROOT_CERT_PATH=
PAY_ALIPAY_RETURN_URL=
PAY_ALIPAY_MODE=0

PAY_LOG_ENABLE=true
PAY_LOG_LEVEL=info
PAY_HTTP_TIMEOUT=10
PAY_HTTP_CONNECT_TIMEOUT=5
```

支付配置统一维护在 `config/pay.php`。RC、OA 以及后续其他业务模块共用同一套微信和支付宝商户账号。

私钥和证书配置支持证书内容或服务器上的绝对文件路径。建议生产环境使用文件路径，并确保文件不在 Web 可访问目录内。

生产环境必须配置真实的平台公钥和商户信息，不得跳过通知验签。
