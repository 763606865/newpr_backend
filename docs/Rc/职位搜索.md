# 职位搜索（求职者）

## 说明

- 路由前缀：`/rc`
- 鉴权：均需 `Bearer Token`，并使用 `auth:rc`
- 适用对象：求职者身份（`identity_type = 1`）
- 成功响应：`api_response()`，结构为 `code` + `data` + `meta`
- 业务错误：`error()`，结构为 `code` + `message` + `meta`
- 搜索引擎：基于 Laravel Scout + Elasticsearch，仅返回对求职者公开的在招职位

### 与招聘方职位接口的区别

| 对比项 | `GET /rc/jobs` | `GET /rc/talent/jobs` |
|--------|----------------|------------------------|
| 适用身份 | 招聘方（已绑定企业） | 求职者 |
| 数据范围 | 仅当前绑定企业的职位（含草稿） | 全平台已发布且未过期的职位 |
| 搜索能力 | 无关键词时走数据库；有 `keyword` 时搜本企业职位 | 全文搜索 + 多条件筛选 |
| 响应序列化 | `RcJobResource` | `RcJobResource`（含 `company`、`position`） |

---

## 公共数据结构

### 职位对象（`RcJobResource`）

字段说明与 [职位.md](./职位.md) 中「职位对象」一致。列表项额外可能包含：

| 字段 | 类型 | 说明 |
|------|------|------|
| `company` | object\|null | 发布企业，`id` + `name`（列表预加载时返回） |
| `position` | object\|null | 常用职位详情（列表预加载时返回） |

### 列表分页

列表接口 `data` 为 Laravel 分页结构：`data`（条目数组）、`total`、`per_page`、`current_page`、`last_page` 等。

### 与职位推荐接口的区别

| 对比项 | `GET /rc/talent/jobs` | `GET /rc/talent/jobs/recommend` |
|--------|------------------------|----------------------------------|
| 鉴权 | 必须登录 + 求职者身份 | **可选登录** |
| 筛选来源 | 用户主动传 Query 参数 | 系统按策略推导筛选条件 |
| 响应额外字段 | 无 | `data.recommendation`（策略与已应用筛选） |

## 1) 推荐职位

- 接口：`GET /rc/talent/jobs/recommend`
- 描述：按推荐策略返回在招职位，无需登录；登录且填写求职意向时自动切换策略
- 鉴权：可选 `Bearer Token`（`auth:rc`）

### 推荐策略

| 策略 | 触发条件 | 筛选规则 |
|------|----------|----------|
| `guest_local` | 未登录，或已登录但无有效求职意向 | 当前市（`city_code`）+ 月薪下限 ≥ 10000 |
| `intention` | 已登录，且主简历存在有效求职意向 | 意向城市、职位类型、工作性质、薪资区间 |

登录用户额外规则：已投递（非撤回）的职位不会出现在推荐列表中。

有效求职意向：至少填写城市、职位类型、行业、工作性质或薪资区间中的一项。

> 行业字段（`expected_industry_codes`）目前仅写入 `recommendation.meta`，待职位侧补齐行业索引后再参与筛选（`industry_filter_pending = true`）。

### Query 参数

| 字段 | 是否必填 | 说明 |
|------|----------|------|
| `city_code` | 否 | 当前城市（市级区划 `code`）；未登录时建议必传，也可通过 Header `X-City-Code` 传递 |
| `per_page` | 否 | 每页条数，默认 15，最大 100 |

### 成功响应补充字段

分页结构同搜索接口，额外包含：

| 字段 | 说明 |
|------|------|
| `data.recommendation.strategy` | 本次使用的策略：`guest_local` / `intention` |
| `data.recommendation.applied_filters` | 实际传给搜索引擎的筛选条件 |
| `data.recommendation.sort` | 排序字段与方向 |

## 2) 职位详情

- 接口：`GET /rc/talent/jobs/{id}`
- 描述：查看单个在招职位详情，含企业与职位类别信息
- 鉴权：可选 `Bearer Token`（`auth:rc`）

### 路径参数

| 字段 | 说明 |
|------|------|
| `id` | 职位 ID |

### 可见规则

与搜索列表一致，仅返回已发布且未过期的职位；草稿、暂停、关闭、过期职位返回 `404`。

### 成功响应

返回完整 `RcJobResource`，预加载 `company`、`position`。

登录用户额外返回：

| 字段 | 类型 | 说明 |
|------|------|------|
| `is_applied` | bool | 当前用户是否已投递该职位（不含已撤回记录） |
| `is_favorited` | bool | 当前用户是否已收藏该职位 |

未登录时不返回 `is_applied`、`is_favorited` 字段。

### 成功响应示例（已登录且已投递）

```json
{
  "code": 200,
  "data": {
    "id": 1,
    "title": "Laravel 工程师",
    "company": {
      "id": 1,
      "name": "南昌示例科技有限公司"
    },
    "is_applied": true,
    "is_favorited": false
  }
}
```

## 2.0) 我收藏的职位列表

- 接口：`GET /rc/talent/favorites/jobs`
- 描述：返回当前求职者收藏的职位列表，按收藏时间倒序
- 鉴权：需 `Bearer Token` + 求职者身份
- 列表项含 `is_favorited`、`is_applied`、`favorited_at`

完整字段说明见 [收藏.md](./收藏.md)。

---

## 2.1) 收藏职位

- 接口：`POST /rc/talent/jobs/{id}/favorite`
- 描述：求职者收藏指定在招职位
- 鉴权：需 `Bearer Token` + 求职者身份

### 成功响应

```json
{
  "code": 200,
  "data": {
    "is_favorited": true
  }
}
```

### 业务失败

| `code` | `message` |
|--------|-----------|
| `422` | 请先切换为求职者身份。 |
| `404` | 职位不存在或已下架。 |

---

## 2.2) 取消收藏职位

- 接口：`DELETE /rc/talent/jobs/{id}/favorite`
- 描述：求职者取消收藏指定职位
- 鉴权：需 `Bearer Token` + 求职者身份

### 成功响应

```json
{
  "code": 200,
  "data": {
    "is_favorited": false
  }
}
```

## 3) 搜索职位

- 接口：`GET /rc/talent/jobs`
- 描述：求职者按关键词与条件搜索在招职位，按 `published_at` 倒序

### Query 参数

| 字段 | 是否必填 | 说明 |
|------|----------|------|
| `keyword` | 否 | 全文搜索关键词；匹配职位名称、编码、描述、要求、福利、关键词、企业名、职位类别等 |
| `city_code` | 否 | 工作城市编码（市级区划 `code`，来源 `GET /rc/meta/areas`） |
| `employment_type` | 否 | 用工类型，见 [RcJobEmploymentType](#rcjobemploymenttype) |
| `education_level` | 否 | 最低学历要求，见 [RcEducationLevel](#rceducationlevel) |
| `position_code` | 否 | 职位类别编码，对应 `GET /rc/meta/positions` 中 `code` |
| `company_id` | 否 | 指定企业 ID |
| `experience_min` | 否 | 最低经验年限下限（年，含） |
| `experience_max` | 否 | 最高经验年限上限（年，含） |
| `salary_min` | 否 | 期望薪资下限（与职位薪资区间求交集） |
| `salary_max` | 否 | 期望薪资上限（与职位薪资区间求交集） |
| `per_page` | 否 | 每页条数，默认 15，最大 100 |

### 关键词匹配范围

`keyword` 会在以下索引字段中检索：

| 分类 | 匹配内容 |
|------|----------|
| 基本信息 | `title`、`code` |
| 企业与类别 | `company_name`、`position_name`、`position_code` |
| 职位详情 | `description`、`requirement`、`benefit`、`keywords` |
| 地点 | `workplace`、`city_code` |

### 公开可见规则

仅满足以下条件的职位会出现在搜索结果中：

- `status = 1`（已发布）
- `expired_at` 为空，或未过期

草稿、暂停、关闭、过期职位不会返回。

### 请求示例

```http
GET /rc/talent/jobs?keyword=Laravel&city_code=360100&employment_type=1&salary_min=15000
Authorization: Bearer {token}
```

### 业务错误

| `code` | `message` |
|--------|-----------|
| `422` | 请先切换为求职者身份。 |

### 规则

- 须先通过 `POST /rc/auth/refresh-token` 切换为求职者身份
- 不传 `keyword` 时返回所有符合筛选条件的在招职位
- `salary_min` / `salary_max` 表示求职者期望区间，服务端按与职位薪资区间的交集筛选
- 列表项读取 `data.data`；分页信息读取 `data.total`、`data.current_page` 等

## 前端推荐流程

1. 首页未登录：`GET /rc/talent/jobs/recommend?city_code=360100` 展示本地高薪职位
2. 职位详情：`GET /rc/talent/jobs/{id}` 查看岗位详情（支持未登录）
3. 登录后：`POST /rc/auth/refresh-token` 切换求职者身份
4. 完善简历与求职意向后：继续调用 `GET /rc/talent/jobs/recommend`（自动走 `intention` 策略）
5. 主动筛选：`GET /rc/meta/areas`、`GET /rc/meta/positions` 加载字典后调用 `GET /rc/talent/jobs`
6. 投递简历：见 [投递.md](./投递.md)

| 值 | 含义 |
|----|------|
| `1` | 高中/中专 |
| `2` | 专科 |
| `3` | 本科 |
| `4` | 硕士 |
| `5` | 博士 |
| `6` | 其他 |
