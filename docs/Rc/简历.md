# 简历

## 说明

- 路由前缀：`/rc`
- 鉴权：均需 `Bearer Token`，并且使用 `auth:rc`
- 适用对象：求职者身份
- 返回格式：
  - 成功：`api_response()`，结构为 `code` + `data` + `meta`
  - 业务错误：`error()`，结构为 `code` + `message` + `meta`

## 公共数据结构

### 简历对象（Resume）

| 字段 | 类型 | 说明 |

| `current_identity` | int | 当前身份 |
| `work_start_date` | string\|null | 参加工作日期 |
| `work_years` | int\|null | 工作年限 |
| `current_salary` | string\|null | 当前/期望薪资 |
| `salary_remark` | string\|null | 薪资备注 |
| `recruit_source` | string\|null | 招聘信息获取来源 |
| `highest_education_level` | int\|null | 最高学历 |
| `is_fresh_graduate` | int | 是否应届生 |

| `current_city_code` | string\|null | 现居住城市编码 |

| `created_at` | string\|null | 创建时间 |
| `updated_at` | string\|null | 更新时间 |

### `source_type` 枚举值

| 值 | 含义 |
|----|------|
| `1` | 上传 |
| `2` | 解析 |
| `3` | 手工创建 |
| `4` | 导入 |

### `status` 枚举值

| 值 | 含义 |
|----|------|
| `1` | 正常 |
| `0` | 停用 |

### 列表响应中的分页结构

`GET /rc/resumes` 会额外返回分页信息：

| 字段 | 类型 | 说明 |
|------|------|------|
| `current_page` | int | 当前页 |
| `per_page` | int | 每页条数 |
| `total` | int | 总数量 |
| `last_page` | int | 最后一页 |

## 3) 新增简历

- 接口：`POST /rc/resumes`
- 鉴权：Bearer Token（`auth:rc`）
- 描述：新增一份简历；若当前用户没有主简历，则新建简历自动设为主简历

### 请求参数

```json
{
  "title": "求职简历",
  "full_name": "张三",
  "phone": "13800138000",
  "email": "zhangsan@example.com",
  "gender": 1,
  "is_primary": 0,
  "status": 1,
  "source_type": 3
}
```

### 字段规则

- `title`：必填，字符串，最大 `255`
- `full_name`：必填，字符串，最大 `50`
- `phone`：必填，字符串，最大 `20`
- `email`：必填，合法邮箱，最大 `100`
- `is_primary`：可选，布尔值
- `status`：可选，`0` 或 `1`
- `source_type`：可选，`1` / `2` / `3` / `4`
- 其余字段均为可选扩展字段，见 `RcResumeResource` 字段说明

- `source_type` 未传时默认 `3`（手工创建）
- `status` 未传时默认 `1`（正常）

## 4) 编辑简历

- 接口：`PUT /rc/resumes/{id}`
- 鉴权：Bearer Token（`auth:rc`）
- 描述：编辑当前用户自己的简历；可切换主简历

### 路径参数

| 参数 | 类型 | 说明 |
|------|------|------|
| `id` | int | 简历 ID |

### 请求参数

```json
{
  "title": "更新后的简历名称",
  "full_name": "张三",
  "phone": "13800138000",
  "email": "zhangsan@example.com",
  "is_primary": 1
}
```

### 字段规则

- 规则与新增接口基本一致
- 所有字段均支持部分更新
- 若传入 `is_primary = 1`，会将当前简历设为主简历，并取消同用户其他简历的主状态

## 5) 前端对接建议

- 列表页直接使用 `data.resumes`
- 详情页直接使用 `data.resume`
- 编辑页可复用新增表单字段
- `is_primary` 建议前端做成单选/开关，避免同一用户出现多个主简历的误操作
- `page_size` 建议前端默认传 `15`

## 6) 与简历相关的首页字典接口

首页页面会复用岗位/行业树：

- `GET /cms/home/rc/positions`：返回 `data.positions` 树状结构
- `GET /cms/home/rc/industries`：返回 `data.industries` 树状结构

这两个接口可用于首页跳转、简历编辑页的字典选择、以及后续“填写简历”相关页面复用。
