# 简历

## 说明

- 路由前缀：`/rc`
- 鉴权：均需 `Bearer Token`，并使用 `auth:rc`
- 适用对象：求职者身份
- 成功响应：`api_response()`，结构为 `code` + `data` + `meta`
- 业务错误：`error()`，结构为 `code` + `message` + `meta`

---

### 服务端自动补全字段（无需前端传入）

| 字段 | 触发条件 | 说明 |
|------|----------|------|
| `resume_no` | 创建时 | 自动生成唯一简历编号 |
| `birth_month` | 传入 `birth_date` | 格式化为 `Y-m` |
| `age` | 传入 `birth_date` | 按当前日期计算周岁 |
| `work_years` | 传入 `work_start_date` | 按当前日期计算年数 |
| `work_start_date` | 传入 `work_years` 且未传精确日期 | 按当前年份回推，取对应年份的 `1月1日` |
| `current_residence_city` | 传入/变更 `current_city_code` | 拼接省市区全称，前缀 `中国` |
| `expected_salary_min` / `expected_salary_max` / `expected_salary_unit` | 新增/编辑/删除求职意向 | 取**最近更新**的一条意向薪资 |
| `highest_education_level` | 新增/编辑/删除教育经历 | 取全部教育经历中的**最高学历** |
| `work_start_date` / `work_years` | 新增/编辑/删除工作经历 | 取全部工作经历中**最早开始日期**并计算年限 |
| `is_fresh_graduate` | 变更 `current_identity` / `work_years` | 当 `current_identity = 学生` 且 `work_years = 0` 时为 `1` |
| `current_identity` | 新增/编辑/删除求职意向、教育经历、工作经历 | 有工作经历为职场人；意向应届生/在读为学生；离职找工作中为待业 |
| `source_type` | 创建时 | 模型默认 `3`（手工创建） |
| `status` | 创建时 | 模型默认 `1`（正常） |

## 1) 简历列表

- 接口：`GET /rc/resumes`
- 描述：返回当前登录用户的简历列表，按 `is_primary DESC -> updated_at DESC -> id DESC` 排序

### Query 参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `per_page` | int | `15` | 每页条数，最小 `1`，最大 `100` |

## 3) 新增简历

- 接口：`POST /rc/resumes`
- 描述：新增一份简历

### 请求示例

```json
{
  "title": "求职简历",
  "full_name": "张三",
  "phone": "13800138000",
  "email": "zhangsan@example.com",
  "gender": 1,
  "birth_date": "1998-05-20",
  "native_place": "360100",
  "household_register": "360100",
  "current_city_code": "360100",
  "is_primary": 0
}
```

### 字段规则

- 以下规则与 `app/Rc/Requests/ResumeStoreRequest.php` 对齐（共享 `ResumeRequestRules`）：

| 字段 | 是否必填 | 类型/规则 | 说明 |
|------|----------|-----------|------|
| `title` | 否 | `nullable`, `string`, `max:255` | 简历名称 |
| `full_name` | 是 | `required`, `string`, `max:50` | 姓名 |
| `avatar` | 否 | `nullable`, `string`, `max:255` | 头像 OSS 相对路径；可先调用 `POST /rc/upload` 取 `path` 写入，展示用响应中的 `display_avatar` |
| `gender` | 否 | `nullable`, `integer`, `min:0`, `max:2` | 性别枚举：`0=未知`、`1=男`、`2=女` |
| `id_card` | 否 | `nullable`, `string`, `size:18` | 身份证号 |
| `nation` | 否 | `nullable`, `string`, `max:20` | 民族 |
| `birth_date` | 否 | `nullable`, `date_format:Y-m-d` | 出生日期 |
| `marital_status` | 否 | `nullable`, `integer`, `min:0`, `max:4` | 婚姻状况：`0=未知`、`1=未婚`、`2=已婚`、`3=离异`、`4=丧偶` |
| `political_status` | 否 | `nullable`, `integer`, Enum | 政治面貌，见 [RcPoliticalStatus](#rcpoliticalstatus)，默认 `5`（群众） |

## 4.1) 上传简历附件

- 接口：`POST /rc/resumes/{id}/attachment`
- 描述：为指定简历上传 PDF/Word 附件，写入 OSS 并更新简历的 `file_*` 字段；后续可基于附件做 AI 解析回填。与通用 `POST /rc/upload` 分离，便于独立演进解析流程。
- Content-Type：`multipart/form-data`

### 路径参数

| 参数 | 类型 | 说明 |
|------|------|------|
| `id` | int | 简历 ID（须属于当前登录用户） |

### 请求参数

| 字段 | 是否必填 | 类型/规则 | 说明 |
|------|----------|-----------|------|
| `file` | 是 | `file`, `mimes:pdf,doc,docx`, `max:128000`（KB） | 简历附件 |

### 请求示例

```http
POST /rc/resumes/1/attachment
Content-Type: multipart/form-data

file: (binary) resume.pdf
```

### 成功响应

- 返回完整 `RcResumeResource`，其中：
  - `file_url`：OSS 相对路径
  - `display_file_url`：可访问 URL
  - `file_name` / `file_ext`：原始文件名及后缀
  - `source_type`：自动设为 `1`（上传）
  - `text_content` / `parsed_data`：重置为 `null`，等待后续解析

```json
{
  "code": 200,
  "data": {
    "id": 1,
    "file_url": "uploads/rc/resume/2026/06/03/abc123.pdf",
    "display_file_url": "https://cdn.example.com/uploads/rc/resume/2026/06/03/abc123.pdf",
    "file_name": "resume.pdf",
    "file_ext": "pdf",
    "source_type": 1,
    "text_content": null,
    "parsed_data": null
  },
  "meta": {
    "timestamp": 1748866200.1234,
    "response_time": 0.0123
  }
}
```

### 业务规则

- 仅允许上传当前用户自己的简历附件
- 若简历已有附件，上传新文件后会删除 OSS 上的旧附件（删除失败不影响新附件绑定）
- 重新上传会清空 `text_content`、`parsed_data`，以便触发新一轮 AI 解析

### 失败响应

| 场景 | HTTP | `code` | `message` |
|------|------|--------|-----------|
| 简历不存在或不属于当前用户 | 200 | 404 | 简历不存在。 |
| 文件类型/大小不合法 | 422 | - | Laravel 校验错误 |
| OSS 上传失败 | 200 | 500 | 简历附件上传失败: ... |

## 20) 简历扩展模块接口总览

以下 6 组接口均遵循与工作/教育经历相同的 REST 规范：

- 鉴权：`Bearer Token` + `auth:rc`
- 仅允许操作当前用户自己的简历；简历或子项不存在时返回 `404`
- 列表按 `sort DESC -> id DESC` 排序
- 列表响应位于 `data.{plural}`；详情/新增/编辑响应直接位于 `data`
- 删除成功时 `data` 为空对象 `{}`

| 模块 | 列表 | 详情 | 新增 | 编辑 | 删除 |
|------|------|------|------|------|------|
| 项目经历 | `GET /rc/resumes/{id}/projects` | `GET .../projects/{projectId}` | `POST .../projects` | `PUT .../projects/{projectId}` | `DELETE .../projects/{projectId}` |
| 培训经历 | `GET /rc/resumes/{id}/trainings` | `GET .../trainings/{trainingId}` | `POST .../trainings` | `PUT .../trainings/{trainingId}` | `DELETE .../trainings/{trainingId}` |
| 语言能力 | `GET /rc/resumes/{id}/languages` | `GET .../languages/{languageId}` | `POST .../languages` | `PUT .../languages/{languageId}` | `DELETE .../languages/{languageId}` |
| 专业技能 | `GET /rc/resumes/{id}/skills` | `GET .../skills/{skillId}` | `POST .../skills` | `PUT .../skills/{skillId}` | `DELETE .../skills/{skillId}` |
| 证书/荣誉 | `GET /rc/resumes/{id}/certificates` | `GET .../certificates/{certificateId}` | `POST .../certificates` | `PUT .../certificates/{certificateId}` | `DELETE .../certificates/{certificateId}` |
| 个人作品 | `GET /rc/resumes/{id}/portfolios` | `GET .../portfolios/{portfolioId}` | `POST .../portfolios` | `PUT .../portfolios/{portfolioId}` | `DELETE .../portfolios/{portfolioId}` |

## 前端对接建议

- 列表页读取 `data.data`
- 分页读取 `data.current_page`、`data.per_page`、`data.total`、`data.last_page`
- 详情、新增、编辑接口的简历对象均直接位于 `data`
- `is_primary` 建议做成单选/开关，避免误操作
- 求职意向列表读取 `data.intentions`；详情/新增/编辑直接位于 `data`
- 工作经历列表读取 `data.works`；详情/新增/编辑直接位于 `data`
- 教育经历列表读取 `data.educations`；详情/新增/编辑直接位于 `data`
- 项目经历列表读取 `data.projects`；详情/新增/编辑直接位于 `data`
- 培训经历列表读取 `data.trainings`；详情/新增/编辑直接位于 `data`
- 语言能力列表读取 `data.languages`；详情/新增/编辑直接位于 `data`
- 专业技能列表读取 `data.skills`；详情/新增/编辑直接位于 `data`
- 证书/荣誉列表读取 `data.certificates`；详情/新增/编辑直接位于 `data`
- 个人作品列表读取 `data.portfolios`；详情/新增/编辑直接位于 `data`
- 一份简历支持多条求职意向，前端可做"添加/删除意向"功能
- 一份简历支持多条工作经历、教育经历，前端可做"添加/删除经历"功能
- `native_place`、`household_register`、`current_city_code` 均传市级 `code`，选项来自区划元数据
- 不要传 `current_residence_city`，展示时直接读响应中的该字段即可
- 头像展示用 `display_avatar`，编辑提交仍用 `avatar`（OSS `path`）
- 个人作品展示用 `display_url` / `display_cover_url`，编辑提交仍用 `url` / `cover_url`（OSS `path`）
