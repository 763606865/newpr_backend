# 简历

## 说明

- 路由前缀：`/rc`
- 鉴权：均需 `Bearer Token`，并使用 `auth:rc`
- 适用对象：求职者身份
- 成功响应：`api_response()`，结构为 `code` + `data` + `meta`
- 业务错误：`error()`，结构为 `code` + `message` + `meta`

---

## 1) 简历列表

- 接口：`GET /rc/resumes`
- 描述：返回当前登录用户的简历列表，按 `is_primary DESC -> updated_at DESC -> id DESC` 排序

### Query 参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `per_page` | int | `15` | 每页条数，最小 `1`，最大 `100` |

### 成功响应示例

```json
{
  "code": 200,
  "data": {
    "current_page": 1,
    "data": [
      {
        "id": 1,
        "user_id": 1,
        "resume_no": "RC20260602120000ABC123",
        "title": "求职简历",
        "full_name": "张三",
        "gender": 1,
        "marital_status": 1,
        "current_identity": 1,
        "highest_education_level": 3,
        "expected_salary_unit": 1,
        "source_type": 3,
        "is_primary": 1,
        "status": 1,
        "created_at": "2026-06-02T12:00:00.000000Z",
        "updated_at": "2026-06-02T12:00:00.000000Z"
      }
    ],
    "first_page_url": "http://example.com/rc/resumes?page=1",
    "from": 1,
    "last_page": 1,
    "last_page_url": "http://example.com/rc/resumes?page=1",
    "links": [],
    "next_page_url": null,

  },
  "meta": {
    "timestamp": 1748865600.1234,
    "response_time": 0.0123
  }

```

### 规则

- 仅返回当前 `auth:rc` 用户自己的简历
- 列表项通过 `RcResumeResource` 序列化，位于 `data.data`

## 3) 新增简历

- 接口：`POST /rc/resumes`
- 描述：新增一份简历

### 请求示例

```json
{
  "title": "求职简历",
  "full_name": "张三",
  "phone": "13800138000",
  "email": "zhangsan@example.com",
  "gender": 1,
  "birth_date": "1998-05-20",
  "native_place": "360100",
  "household_register": "360100",
  "current_city_code": "360100",
  "is_primary": 0
}
```

### 字段规则

- 以下规则与 `app/Rc/Requests/ResumeStoreRequest.php` 对齐（共享 `ResumeRequestRules`）：

| 字段 | 是否必填 | 类型/规则 | 说明 |
|------|----------|-----------|------|
| `title` | 否 | `nullable`, `string`, `max:255` | 简历名称 |
| `full_name` | 是 | `required`, `string`, `max:50` | 姓名 |
| `avatar` | 否 | `nullable`, `string`, `max:255` | 头像 OSS 相对路径；可先调用 `POST /rc/upload` 取 `path` 写入，展示用响应中的 `display_avatar` |
| `gender` | 否 | `nullable`, `integer`, `min:0`, `max:2` | 性别枚举：`0=未知`、`1=男`、`2=女` |
| `id_card` | 否 | `nullable`, `string`, `size:18` | 身份证号 |
| `nation` | 否 | `nullable`, `string`, `max:20` | 民族 |
| `birth_date` | 否 | `nullable`, `date_format:Y-m-d` | 出生日期 |
| `marital_status` | 否 | `nullable`, `integer`, `min:0`, `max:4` | 婚姻状况：`0=未知`、`1=未婚`、`2=已婚`、`3=离异`、`4=丧偶` |
| `political_status` | 否 | `nullable`, `string`, `max:20` | 政治面貌 |
| `native_place` | 否 | `nullable`, `string`, `max:100`, `exists:areas,code`（`level=2`） | 籍贯，传市级区划 `code` |
| `current_identity` | 否 | `nullable`, `integer`, `min:0` | 当前身份：`0=其他`、`1=职场人`、`2=学生`、`3=待业` |
| `work_start_date` | 否 | `nullable`, `date_format:Y-m-d` | 参加工作日期 |
| `work_years` | 否 | `nullable`, `integer`, `min:0`, `max:80` | 工作年限（可传，通常由服务端根据 `work_start_date` 计算） |
| `current_salary` | 否 | `nullable`, `string`, `max:50` | 当前/期望薪资 |
| `salary_remark` | 否 | `nullable`, `string`, `max:200` | 薪资备注 |
| `recruit_source` | 否 | `nullable`, `string`, `max:100` | 招聘信息来源 |
| `highest_education_level` | 否 | `nullable`, `integer`, `min:1`, `max:6` | 最高学历：`1=高中/中专`、`2=专科`、`3=本科`、`4=硕士`、`5=博士`、`6=其他` |
| `is_fresh_graduate` | 否 | `nullable`, `boolean` | 是否应届 |
| `expected_salary_min` | 否 | `nullable`, `numeric`, `min:0` | 期望薪资下限 |
| `expected_salary_max` | 否 | `nullable`, `numeric`, `min:0` | 期望薪资上限 |
| `expected_salary_unit` | 否 | `nullable`, `in:1,2,3` | 薪资单位：`1=月`、`2=日`、`3=时` |
| `household_register` | 否 | `nullable`, `string`, `max:100`, `exists:areas,code`（`level=2`） | 户口所在地，传市级区划 `code` |
| `household_register_detail` | 否 | `nullable`, `string`, `max:200` | 户口详细地址 |
| `current_city_code` | 否 | `nullable`, `string`, `max:32`, `exists:areas,code`（`level=2`） | 现居住城市编码（市级） |
| `current_residence_detail` | 否 | `nullable`, `string`, `max:200` | 现居住地详细地址 |
| `residence_country` | 否 | `nullable`, `string`, `max:50` | 现居住国家/地区 |
| `phone` | 是 | `required`, `string`, `max:20` | 联系电话 |
| `email` | 是 | `required`, `email:rfc`, `max:100` | 邮箱 |
| `file_url` | 否 | `nullable`, `string`, `max:255` | 简历文件地址 |
| `file_name` | 否 | `nullable`, `string`, `max:255` | 简历文件名称 |
| `file_ext` | 否 | `nullable`, `string`, `max:16` | 文件后缀 |
| `text_content` | 否 | `nullable`, `string` | 简历文本内容 |
| `parsed_data` | 否 | `nullable`, `array` | 解析结构化结果 |
| `is_primary` | 否 | `nullable`, `boolean` | 是否主简历 |

- **不接受**的字段：`birth_month`、`age`、`current_residence_city`、`source_type`、`status`、`extra`（由服务端维护或自动补全）。
- 区划 `code` 数据来源：`GET /rc/meta/areas` 或 `GET /rc/meta` 中的 `areas` 树，取**市级**节点 `code`。

### 成功响应示例

```json
{
  "code": 200,
  "data": {
    "id": 1,
    "user_id": 1,
    "resume_no": "RC20260602120000ABC123",
    "title": "求职简历",
    "full_name": "张三",
    "source_type": 3,
    "is_primary": 1,
    "status": 1,
    "created_at": "2026-06-02T12:00:00.000000Z",
    "updated_at": "2026-06-02T12:00:00.000000Z"
  },
  "meta": {
    "timestamp": 1748865600.1234,
    "response_time": 0.0123
  }
}
```

### 规则

- 新增时自动生成 `resume_no`
- 若当前用户没有主简历，新建简历自动设为主简历（`is_primary = 1`）
- 若传入 `is_primary = 1`，会取消同用户其他主简历，并尝试用主简历信息补全用户资料中空字段
- `source_type`、`status` 使用模型默认值，前端无需传入

## 4) 编辑简历

- 接口：`PUT /rc/resumes/{id}`
- 描述：编辑当前用户自己的简历；支持切换主简历

### 路径参数

| 参数 | 类型 | 说明 |
|------|------|------|
| `id` | int | 简历 ID |

### 请求示例

```json
{
  "title": "更新后的简历名称",
  "current_city_code": "360100",
  "is_primary": 1
}
```

### 字段规则

- 与新增接口字段集一致，所有字段均带 `sometimes`（部分更新）；规则定义见 `ResumeRequestRules::resumeFieldRules(sometimes: true)`。
- `title`：`sometimes`, `nullable`, `string`, `max:255`
- `full_name` / `phone` / `email`：若出现在请求体中，则分别需满足与新增接口相同的 `required` 及格式规则。
- 其余字段规则与「3) 新增简历」字段表相同，均在规则前增加 `sometimes`。
- **不接受**的字段同新增接口：`birth_month`、`age`、`current_residence_city`、`source_type`、`status`、`extra`。

- 说明：`条件必填` 表示仅当该字段出现在请求体中时，字段值不能为空。
- 若传入 `is_primary = 1`，会将当前简历设为主简历，并取消同用户其他主简历。
- 变更 `current_city_code` 时，服务端会自动刷新 `current_residence_city`。

### 成功响应示例

```json
{
  "code": 200,
  "data": {
    "id": 1,
    "user_id": 1,
    "resume_no": "RC20260602120000ABC123",
    "title": "更新后的简历名称",
    "source_type": 3,
    "is_primary": 1,
    "status": 1,
    "created_at": "2026-06-02T12:00:00.000000Z",
    "updated_at": "2026-06-02T12:10:00.000000Z"
  },
  "meta": {
    "timestamp": 1748866200.1234,
    "response_time": 0.0123
  }
}
```

### 业务失败响应示例

```json
{
  "code": 404,
  "message": "简历不存在。",
  "meta": {
    "timestamp": 1748866200.1234,
    "response_time": 0.0123
  }
}
```

## 前端对接建议

- 列表页读取 `data.data`
- 分页读取 `data.current_page`、`data.per_page`、`data.total`、`data.last_page`
- 详情、新增、编辑接口的简历对象均直接位于 `data`
- `is_primary` 建议做成单选/开关，避免误操作
- 求职意向列表读取 `data.intentions`；详情/新增/编辑直接位于 `data`
- 工作经历列表读取 `data.works`；详情/新增/编辑直接位于 `data`
- 教育经历列表读取 `data.educations`；详情/新增/编辑直接位于 `data`
- 一份简历支持多条求职意向，前端可做"添加/删除意向"功能
- 一份简历支持多条工作经历、教育经历，前端可做"添加/删除经历"功能
- `native_place`、`household_register`、`current_city_code` 均传市级 `code`，选项来自区划元数据
- 不要传 `current_residence_city`，展示时直接读响应中的该字段即可
- 头像展示用 `display_avatar`，编辑提交仍用 `avatar`（OSS `path`）
