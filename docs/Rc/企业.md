# 企业（招聘方绑定/注册）

## 说明

- 路由前缀：`/rc`
- 鉴权：均需 `Bearer Token`，并使用 `auth:rc`
- 适用对象：招聘方身份（`identity_type = 2`）
- 成功响应：`api_response()`，结构为 `code` + `data` + `meta`
- 业务错误：`error()`，结构为 `code` + `message` + `meta`

> 绑定或注册成功后，招聘方身份的 `has_basic_info` 为 `true`（`organization_type = company` 且 `organization_id` 不为空）。

### 前端入参说明

注册接口仅提交企业主体字段与营业执照 OSS 路径；**证件、联系人由服务端自动写入** `company_licenses`、`company_contacts`（未知字段使用默认值，见 [服务端自动填充](#服务端自动填充)）。

绑定接口仅提交 `company_id` 与 `job_title`，不重复写入证件/联系人（企业资料由 lookup 或历史注册产生）。

营业执照需先 `POST /rc/upload`，将 `data.path` 填入 `licenses_file_path`。

---

## 服务端自动填充

注册企业（`POST /rc/companies`）时自动创建：

### `company_licenses`（1 条营业执照）

| 字段 | 默认值来源 |
|------|------------|
| `license_type` | `1`（营业执照） |
| `name` | `营业执照` |
| `license_no` | `credit_code` |
| `file_url` / `file_name` / `file_ext` | 解析 `licenses_file_path`（未传则为 `null`） |
| `is_primary` | `1` |
| `issuer` / `issue_date` / `expire_date` | `null` |

### `company_contacts`（2 条）

| 记录 | `contact_type` | 默认填充 |
|------|----------------|----------|
| 法定代表人 | `1` | `name` ← `legal_person`，`phone` ← `contact_phone`，`position` = 法定代表人，`address` ← `address`，`is_primary` = 1 |
| 企业联系人 | `3` | 同上，`position` = 企业联系人，`is_primary` = 0 |

## 公共数据结构

### 企业对象（`RcCompanyResource`）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | int | 企业 ID |
| `name` | string | 企业名称 |
| `credit_code` | string\|null | 统一社会信用代码 |
| `legal_person` | string\|null | 法人姓名 |
| `contact_phone` | string\|null | 联系电话 |
| `address` | string\|null | 企业地址 |
| `status` | int | 见 [CompanyStatus](#companystatus) |
| `licenses` | array | 证件列表（lookup / 注册 / 绑定成功时返回） |
| `contacts` | array | 联系人列表 |
| `created_at` / `updated_at` | string\|null | 时间 |

### 企业证件 / 联系人对象

字段说明见历史版本；`file_url` 为 OSS 相对路径，`display_file_url` 为可访问 URL。

### 身份对象（`identity`）

| 字段 | 类型 | 说明 |
|------|------|------|
| `organization_type` | string\|null | 企业为 `company` |
| `organization_id` | int\|null | 企业 ID |
| `job_title` | string\|null | 岗位名称 |
| `has_basic_info` | bool | 是否已完成基础信息 |

## 1) 查询企业

- 接口：`GET /rc/companies/lookup`

### 请求参数（Query）

| 字段 | 是否必填 | 规则 | 说明 |
|------|----------|------|------|
| `credit_code` | 是 | `required`, `string`, `size:18` | 统一社会信用代码 |

### 成功响应 `data`

| 字段 | 说明 |
|------|------|
| `exists` | 是否已注册 |
| `company` | 企业对象（含 `licenses`、`contacts`），不存在时为 `null` |

---

## 2) 绑定已存在企业

- 接口：`POST /rc/companies/bind`
- Content-Type：`application/json`

### 请求参数

| 字段 | 是否必填 | 规则 | 说明 |
|------|----------|------|------|
| `company_id` | 是 | `required`, `exists:companies,id`（未软删） | 企业 ID（来自 lookup 的 `company.id`） |
| `job_title` | 是 | `required`, `string`, `max:50` | 岗位名称 |

### 请求示例

```json
{
  "company_id": 12,
  "job_title": "招聘经理"
}
```

### 成功响应 `data`

| 字段 | 说明 |
|------|------|
| `company` | 企业对象（含已有证件、联系人） |
| `identity` | 绑定后的招聘方身份 |

### 业务失败

| `code` | `message` |
|--------|-----------|
| `422` | 请先切换为招聘方身份。 |
| `422` | 您已绑定该企业。 |
| `422` | 该企业已被禁用，无法绑定。 |

> 当前 Token 对应招聘方身份已绑定其他企业时，会**新建一条**招聘方身份行并绑定目标企业（同一用户可拥有多家企业身份，切换见 `POST /rc/auth/refresh-token` + `identity_id`）。

`company_id` 不存在时返回 HTTP `422` 参数校验错误（`errors.company_id`）。

## 3) 注册企业并绑定

- 接口：`POST /rc/companies`
- Content-Type：`application/json`

### 请求参数

| 字段 | 是否必填 | 规则 | 说明 |
|------|----------|------|------|
| `name` | 是 | `required`, `string`, `max:255` | 企业名称 |
| `credit_code` | 是 | `required`, `string`, `size:18` | 统一社会信用代码 |
| `legal_person` | 是 | `required`, `string`, `max:255` | 法人姓名 |
| `contact_phone` | 是 | `required`, `string`, `max:255` | 联系电话 |
| `address` | 否 | `nullable`, `string` | 企业地址 |
| `job_title` | 是 | `required`, `string`, `max:50` | 岗位名称 |
| `licenses_file_path` | 否 | `nullable`, `string`, `max:500` | 营业执照 OSS 路径（`POST /rc/upload` 的 `path`） |

### 请求示例

```json
{
  "name": "南昌示例科技有限公司",
  "credit_code": "91360100MA0000000X",
  "legal_person": "李四",
  "contact_phone": "13900000000",
  "address": "南昌市高新区示例路 88 号",
  "job_title": "HR 总监",
  "licenses_file_path": "uploads/rc/file/2026/06/04/license.pdf"
}
```

### 成功响应

- `data.company`：含自动生成的 `licenses`（营业执照）、`contacts`（法定代表人 + 企业联系人）
- `data.identity`：已绑定身份
- `company.status` = `2`（审批中）

### 业务失败

| `code` | `message` |
|--------|-----------|
| `422` | 请先切换为招聘方身份。 |
| `422` | 您已绑定该企业。 |
| `422` | 企业已存在，请直接绑定。 |

> 当前身份已绑定企业时，注册新企业同样会新建身份行；若信用代码对应企业已在库中且您尚未绑定，请走「绑定已存在企业」接口。

---

## 前端推荐流程

1. `POST /rc/auth/refresh-token`，`identity_type = 2`
2. `GET /rc/companies/lookup?credit_code=...`
3. **已存在**：记下 `company.id` → `POST /rc/companies/bind`（`company_id` + `job_title`）
4. **不存在**：上传执照 → `POST /rc/companies`（主体字段 + `licenses_file_path` + `job_title`）
5. `GET /rc/auth/me` 确认 `has_basic_info`

## 枚举参考

### CompanyStatus

| 值 | 含义 |
|----|------|
| `0` | 禁用 |
| `1` | 启用 |
| `2` | 审批中（Rc 注册默认） |

### CompanyLicenseType

| 值 | 含义 |
|----|------|
| `1` | 营业执照 |
| `2` | 食品经营许可证 |
| `3` | 资质证书 |
| `4` | 其他 |

### CompanyContactType

| 值 | 含义 |
|----|------|
| `1` | 法定代表人 |
| `2` | 股东 |
| `3` | 联系人 |
| `4` | 实际控制人 |
| `5` | 其他 |
