# 招聘方 - 投递记录

对应实现：`app/Rc/Controllers/CompanyApplicationController.php`

## 1) 投递记录列表

- 方法：`GET`
- URI：`/rc/companies/applications`
- 鉴权：是（需切换到招聘方身份并绑定企业）

### 请求参数（Query）

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| per_page | integer | 否 | 每页数量，默认 15 |
| job_id | integer | 否 | 按职位过滤 |
| status | integer | 否 | 按投递状态过滤（枚举值） |
| candidate_user_id | integer | 否 | 按候选人 user_id 过滤 |

### 示例请求

```
GET /rc/companies/applications?per_page=20&job_id=123
Authorization: Bearer {token}
```

### 示例响应（200）

```json
{
  "code": 200,
  "data": [
    {
      "id": 123,
      "company_id": 45,
      "job_id": 678,
      "candidate_user_id": 999,
      "resume_snapshot": {},
      "status": 1,
      "applied_at": "2026-07-14T10:00:00Z"
    }
  ],
  "meta": {
    "current_page": 1,
    "per_page": 20,
    "total": 1
  }
}
```

## 2) 查询指定职位投递记录

- 方法：`GET`
- URI：`/rc/companies/applications/check`
- 鉴权：是（需切换到招聘方身份并绑定企业）
- 说明：招聘方根据职位与求职者用户 / 简历查询本企业是否已存在投递记录。

### 请求参数（Query）

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| job_id | integer | 是 | 职位 ID，必须是未删除职位 |
| candidate_user_id | integer | 否 | 求职者用户 ID；与 `resume_id` 至少传一个 |
| resume_id | integer | 否 | 简历 ID；与 `candidate_user_id` 至少传一个 |

### 示例请求

```
GET /rc/companies/applications/check?job_id=123&resume_id=456
Authorization: Bearer {token}
```

### 示例响应（已存在）

```json
{
  "code": 200,
  "data": {
    "id": 123,
    "company_id": 45,
    "job_id": 123,
    "resume_id": 456,
    "candidate_user_id": 999,
    "candidate_external_user_id": "8K3mQxYp9aV2nL0sR7tBcD4eFgHiJkLm",
    "status": 1,
    "status_label": "筛选中"
  },
  "meta": {
    "timestamp": 1784785200.1234,
    "response_time": 0.0123
  }
}
```

### 示例响应（不存在或职位不属于当前企业）

```json
{
  "code": 200,
  "data": null,
  "meta": {
    "timestamp": 1784785200.1234,
    "response_time": 0.0123
  }
}
```

### 业务规则

- 仅查询当前招聘方绑定企业下的投递记录。
- 若 `job_id` 对应职位不属于当前企业，返回 `data: null`。
- 若同时传入 `candidate_user_id` 与 `resume_id`，两个条件会同时生效。
- 返回最新一条匹配记录：`id desc`。

## 3) 投递记录详情

- 方法：`GET`
- URI：`/rc/companies/applications/{id}`
- 鉴权：是（需切换到招聘方身份并绑定企业）
- 说明：招聘方查看本企业投递详情。行为与旧接口 `GET /rc/applications/{id}` 的招聘方视角一致。

### Path 参数

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| id | integer | 是 | 投递记录 ID |

### 示例请求

```
GET /rc/companies/applications/123
Authorization: Bearer {token}
```

### 示例响应（200）

```json
{
  "code": 200,
  "data": {
    "id": 123,
    "company_id": 45,
    "job_id": 678,
    "candidate_user_id": 999,
    "status": 1,
    "status_label": "筛选中",
    "candidate": {
      "full_name": "候选人甲",
      "external_user_id": "8K3mQxYp9aV2nL0sR7tBcD4eFgHiJkLm"
    },
    "resume_snapshot": {
      "full_name": "候选人甲",
      "phone": "138****8000",
      "email": "can******@example.com"
    }
  },
  "meta": {
    "timestamp": 1784785200.1234,
    "response_time": 0.0123
  }
}
```

### 业务规则

- 仅能查看当前招聘方绑定企业下的投递记录。
- 若投递状态为「待处理」，查看详情时会自动流转为「筛选中」。
- 返回 `candidate.external_user_id`，用于招聘方发起 IM 沟通。
- `resume_snapshot` 中联系方式会脱敏。

### 错误示例（投递不存在）

```json
{
  "code": 404,
  "message": "投递记录不存在。"
}
```

## 4) 招聘方投递操作

以下接口均需切换到招聘方身份并绑定企业，且只能操作当前企业下的投递记录。业务行为与旧接口 `POST /rc/applications/{id}/...` 的招聘方侧逻辑一致。

### 4.1 邀请面试

- 方法：`POST`
- URI：`/rc/companies/applications/{id}/invite-interview`

#### 请求参数

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| interview_at | datetime | 是 | 面试时间，必须晚于当前时间 |
| mode | integer | 是 | 面试方式，见 `RcInterviewMode` |
| interviewer_user_id | integer | 否 | 面试官用户 ID |
| interviewer_name | string | 否 | 面试官姓名 |
| duration_mins | integer | 否 | 面试时长，1-480 分钟 |
| location | string | 否 | 面试地点 |
| meeting_url | string | 否 | 线上会议链接 |
| note | string | 否 | 备注 |

#### 示例请求

```json
{
  "interview_at": "2026-07-24 10:00:00",
  "mode": 1,
  "meeting_url": "https://meet.example.com/room-1",
  "interviewer_name": "张经理"
}
```

### 4.2 发送 Offer

- 方法：`POST`
- URI：`/rc/companies/applications/{id}/send-offer`

#### 请求参数

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| salary | numeric | 是 | 确认薪资 |
| salary_unit | integer | 否 | 薪资单位，默认月 |
| has_probation | boolean | 否 | 是否有试用期 |
| remuneration_note | string | 否 | 薪酬说明 |
| attendance_note | string | 否 | 考勤说明 |
| entry_date | date | 否 | 入职日期，不早于今天 |
| expire_date | date | 否 | Offer 过期日期，不早于今天 |
| note | string | 否 | 备注 |
| extra | object | 否 | 扩展信息 |

#### 示例请求

```json
{
  "salary": 18000,
  "salary_unit": 1,
  "has_probation": true,
  "remuneration_note": "五险一金，年终奖按公司制度",
  "attendance_note": "周一至周五 9:00-18:00",
  "entry_date": "2026-08-01",
  "extra": {
    "probation_months": 3,
    "probation_salary": "15000.00"
  }
}
```

### 4.3 确认录用

- 方法：`POST`
- URI：`/rc/companies/applications/{id}/hire`

#### 请求参数

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| note | string | 否 | 备注 |

### 4.4 淘汰

- 方法：`POST`
- URI：`/rc/companies/applications/{id}/reject`

#### 请求参数

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| note | string | 否 | 淘汰备注 |

### 成功响应

成功时返回更新后的 `RcApplicationResource`，包含投递状态、职位、企业、候选人摘要、面试邀请或 Offer 信息等。

### 业务错误

| 场景 | code | message |
| --- | --- | --- |
| 未切换招聘方身份或未绑定企业 | 422 | 请先切换为招聘方身份并绑定企业。 |
| 投递不属于当前企业或不存在 | 404 | 投递记录不存在。 |
| 当前状态不可执行该动作 | 422 | 返回对应业务错误文案 |

---

## 错误示例（未绑定企业）

```json
{
  "code": 422,
  "message": "请先切换为招聘方身份并绑定企业。"
}
```
