# 举报

## 说明

- 路由前缀：`/rc`
- 鉴权：需 `Bearer Token`，并使用 `auth:rc`
- 成功响应：`api_response()`，结构为 `code` + `data` + `meta`
- 业务错误：`error()`，结构为 `code` + `message` + `meta`

### 能力范围

用户可以举报以下对象：

| `reportable_type` | 对象 | 对应表 |
|-------------------|------|--------|
| `job` | 职位 | `rc_jobs` |
| `company` | 企业 | `companies` |
| `resume` | 简历 | `rc_resumes` |

提交举报时，服务端会自动记录：

- 当前登录用户：`user_id`
- 当前用户身份：`creator_user_identity_id`
- 举报 IP：`ip`
- User-Agent：`user_agent`
- 举报对象多态字段：`reportable_type` / `reportable_id`

---

## 1) 提交举报

- 接口：`POST /rc/reports`
- 描述：提交职位、企业或简历举报
- 身份要求：必须已登录，并且当前 Token 能解析出用户身份

### 请求参数

| 字段 | 类型 | 是否必填 | 说明 |
|------|------|----------|------|
| `reportable_type` | string | 是 | 举报对象类型：`job` / `company` / `resume` |
| `reportable_id` | int | 是 | 举报对象 ID |
| `reason_type` | int | 是 | 举报原因类型，见 [RcReportReasonType](#rcreportreasontype) |
| `reason` | string\|null | 否 | 举报原因说明，最大 100 字符 |
| `description` | string\|null | 否 | 举报详细说明，最大 2000 字符 |
| `attachments` | string[]\|null | 否 | 举报凭证附件，最多 9 个；每项最大 500 字符，通常为上传后的文件路径 |
| `extra` | object\|null | 否 | 扩展字段 |

### 请求示例：举报职位

```http
POST /rc/reports
Authorization: Bearer {token}
Content-Type: application/json
```

```json
{
  "reportable_type": "job",
  "reportable_id": 12,
  "reason_type": 1,
  "reason": "虚假职位",
  "description": "岗位描述与实际沟通内容不一致。",
  "attachments": [
    "reports/evidence/job-12-1.png"
  ]
}
```

### 请求示例：举报企业

```json
{
  "reportable_type": "company",
  "reportable_id": 3,
  "reason_type": 2,
  "reason": "疑似收费招聘",
  "description": "企业要求先缴纳培训费用。"
}
```

### 请求示例：举报简历

```json
{
  "reportable_type": "resume",
  "reportable_id": 88,
  "reason_type": 3,
  "description": "简历内容疑似包含违规信息。"
}
```

### 成功响应

```json
{
  "code": 200,
  "data": {
    "report": {
      "id": 101,
      "status": 0,
      "reportable_type": "job",
      "reportable_id": 12,
      "created_at": "2026-07-21T09:30:00.000000Z"
    }
  },
  "meta": {
    "timestamp": 1784616600.123,
    "response_time": 0.015
  }
}
```

### 响应字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `report.id` | int | 举报记录 ID |
| `report.status` | int | 处理状态，默认 `0`，见 [RcReportStatus](#rcreportstatus) |
| `report.reportable_type` | string | 举报对象类型 |
| `report.reportable_id` | int | 举报对象 ID |
| `report.created_at` | string | 举报提交时间 |

## 业务失败

| 场景 | `code` | `message` |
|------|--------|-----------|
| 未登录或 Token 失效 | `401` | Token Expired。 |
| 当前 Token 无法解析用户身份 | `422` | 请先选择用户身份。 |
| 举报对象不存在 | `404` | 举报对象不存在。 |
| 参数校验失败 | `422` | Laravel Validation 默认错误结构 |

## 枚举

### `RcReportReasonType`

| 值 | 枚举 | 说明 |
|----|------|------|
| `1` | `FalseInformation` | 虚假信息 |
| `2` | `Fraud` | 诈骗或收费 |
| `3` | `IllegalContent` | 违法违规内容 |
| `4` | `Harassment` | 骚扰或不当联系 |
| `99` | `Other` | 其他 |

### `RcReportStatus`

| 值 | 枚举 | 说明 |
|----|------|------|
| `0` | `Pending` | 待处理 |
| `1` | `Processing` | 处理中 |
| `2` | `Resolved` | 已处理 |
| `3` | `Rejected` | 已驳回 |

---

## 运营后台

举报记录提交后，可在 Filament 运营后台处理：

- 路径：`/admin/rc/reports`
- 功能：查看举报信息、筛选举报对象/原因/状态、填写处理结果、更新处理状态
- 非待处理状态保存时，后台会自动写入当前处理管理员和处理时间
