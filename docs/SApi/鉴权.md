# SApi 加签鉴权

## 说明

- 除另有标注的开放接口外，**所有** `/sapi/*` 业务接口均需通过本文档描述的加签鉴权。
- 中间件：`App\SApi\Middleware\VerifySignatureMiddleware`
- 验签通过后，当前请求可通过 `$request->attributes->get('sapi_client')` 或控制器内 `$this->client()` 获取接入客户端模型（`App\Models\SApi\Client`）。

---

## 请求头

| 请求头 | 必填 | 说明 |
|--------|------|------|
| `X-SApi-App-Key` | 是 | 平台分配的 `app_key` |
| `X-SApi-Timestamp` | 是 | Unix 时间戳（**秒**，纯数字） |
| `X-SApi-Nonce` | 是 | 随机字符串，建议 16 位以上，单次请求唯一 |
| `X-SApi-Sign` | 是 | 请求签名（见下文算法） |

请求头名称可在 `config/sapi.php` 的 `headers` 中配置，默认为上表。

### 时间戳

- 服务端校验：`abs(服务器时间 - X-SApi-Timestamp) <= SAPI_TIMESTAMP_TOLERANCE`（默认 300 秒）。
- 对接方应使用 NTP 同步后的系统时间。

### Nonce 防重放

- 同一 `app_key` + `nonce` 在缓存有效期内不可重复使用。
- 缓存 TTL 为 `时间窗口 × 2`（默认 600 秒）。
- 生产环境建议配置 `SAPI_NONCE_CACHE_STORE=redis`。

### IP 白名单

- 若 `sapi_clients.allowed_ips` 非空，则请求来源 IP 须命中白名单（精确匹配）。
- 为空或未配置时不校验 IP。

## 签名算法

### 步骤

1. 准备待签名字符串 `canonical`（见下方格式）。
2. 计算签名：`sign = hash_hmac('sha256', canonical, app_secret)`（小写十六进制）。
3. 将 `sign` 放入请求头 `X-SApi-Sign`。

### 待签名字符串格式

各行之间使用换行符 `\n`（LF）连接，共 7 行：

```
HTTP_METHOD
PATH
QUERY_STRING
BODY_SHA256_HEX
TIMESTAMP
NONCE
APP_KEY
```

| 行 | 规则 |
|----|------|
| `HTTP_METHOD` | 大写，如 `GET`、`POST`、`PUT`、`DELETE` |
| `PATH` | 请求路径，以 `/` 开头；除根路径 `/` 外去掉尾部 `/`，如 `/sapi/ping` |
| `QUERY_STRING` | Query 参数按 **key 字典序** 排序后，使用 `http_build_query(..., '', '&', PHP_QUERY_RFC3986)` 编码；无参数时为空字符串 |
| `BODY_SHA256_HEX` | 原始请求体的 SHA256 十六进制；**无 body 时用空字符串的 hash**：`hash('sha256', '')` |
| `TIMESTAMP` | 与请求头 `X-SApi-Timestamp` 一致 |
| `NONCE` | 与请求头 `X-SApi-Nonce` 一致 |
| `APP_KEY` | 与请求头 `X-SApi-App-Key` 一致 |

### 重要约定

- 签名使用的 **body 必须是原始字节**，与 HTTP 实际发送内容完全一致。
- `GET` 请求通常无 body，此时 `BODY_SHA256_HEX` 为 `e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855`（空串 SHA256）。
- **不要** 对无 body 的 `GET` 请求附带 `[]` 等 JSON 占位符，否则验签失败。
- `POST` / `PUT` 若发送 JSON，应对 **原始 JSON 字符串** 计算 hash，而不是重新序列化后的变体。

### 示例

请求：

```http
GET /sapi/ping?page=1&foo=bar HTTP/1.1
X-SApi-App-Key: sapi_demo_key
X-SApi-Timestamp: 1717488000
X-SApi-Nonce: 8f3a2b1c9d0e4f5a
```

假设无请求体，`app_secret` 为 `your_app_secret`，则：

```
canonical =
GET\n
/sapi/ping\n
foo=bar&page=1\n
e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855\n
1717488000\n
8f3a2b1c9d0e4f5a\n
sapi_demo_key
```

```
X-SApi-Sign = hash_hmac('sha256', canonical, 'your_app_secret')
```

## 接入示例

### cURL（GET /sapi/ping）

需自行用脚本生成 `TIMESTAMP`、`NONCE`、`SIGN`，示例：

```bash
# 以下为示意，SIGN 须按上文算法计算
curl -X GET "https://example.com/sapi/ping" \
  -H "X-SApi-App-Key: sapi_xxxxxxxx" \
  -H "X-SApi-Timestamp: 1717488000" \
  -H "X-SApi-Nonce: $(openssl rand -hex 8)" \
  -H "X-SApi-Sign: <calculated_sign>"
```

### PHP 参考

```php
function sapiSign(
    string $method,
    string $path,
    array $query,
    string $body,
    string $timestamp,
    string $nonce,
    string $appKey,
    string $appSecret,
): string {
    ksort($query);
    $path = $path === '/' ? $path : rtrim($path, '/');
    $canonical = implode("\n", [
        strtoupper($method),
        $path,
        http_build_query($query, '', '&', PHP_QUERY_RFC3986),
        hash('sha256', $body),
        $timestamp,
        $nonce,
        $appKey,
    ]);

    return hash_hmac('sha256', $canonical, $appSecret);
}

$timestamp = (string) time();
$nonce = bin2hex(random_bytes(8));
$sign = sapiSign('GET', '/sapi/ping', [], '', $timestamp, $nonce, $appKey, $appSecret);

// 将 $timestamp、$nonce、$sign 写入对应请求头后发起 HTTP 请求
```

## 鉴权失败响应

HTTP 状态码：`401 Unauthorized`

```json
{
  "code": 401,
  "message": "SApi 签名校验失败。",
  "meta": {
    "timestamp": 1748865600.1234,
    "response_time": 0.0123
  }
}
```

### 错误信息一览

| `message` | 说明 |
|-----------|------|
| 缺少 SApi 鉴权请求头。 | 未传齐 `X-SApi-*` 四个请求头 |
| SApi 时间戳格式无效。 | `X-SApi-Timestamp` 非纯数字 |
| SApi 请求已过期。 | 超出时间窗口 |
| SApi 应用不存在。 | `app_key` 无效 |
| SApi 应用已停用。 | 客户端 `status = 0` |
| SApi 来源 IP 不在白名单内。 | 来源 IP 未命中白名单 |
| SApi 请求重复。 | `nonce` 已被使用 |
| SApi 签名校验失败。 | 签名不正确或 body/path/query 与签名时不一致 |

## Postman-Pre-request Script 示例

```javascript
// ========== 配置项（从环境变量读取）==========
const appKey = pm.environment.has("zcgz-sapi-app-key") ? pm.environment.get("zcgz-sapi-app-key") : 'Your-App-Key';
const appSecret = pm.environment.has("zcgz-sapi-app-secret") ? pm.environment.get("zcgz-sapi-app-secret") : 'Your-App-Secret';

// ========== 1. 生成时间戳 / 随机串 ==========
const timestamp = Math.floor(Date.now() / 1000).toString();
const nonce = Array(16).fill(0).map(() => Math.random().toString(36).slice(2)).join('').slice(0, 20);

// ========== 2. 获取请求方法 & 路径 ==========
const httpMethod = pm.request.method.toUpperCase();
const realPath = '/' + (pm.request.url.path || []).filter(Boolean).join('/');
const path = '/sapi' + (realPath === '/' ? '' : realPath);

// ========== 3. 处理 QueryString（字典序 + RFC3986）==========
let queryParams = {};
pm.request.url.query.each(item => {
    if (!item.disabled && item.key) queryParams[item.key] = item.value;
});
const sortedQueryKeys = Object.keys(queryParams).sort();
let sortedQuery = {};
sortedQueryKeys.forEach(k => sortedQuery[k] = queryParams[k]);
const queryString = new URLSearchParams(sortedQuery).toString();

// ========== 4. 计算 Body SHA256 ==========
let rawBody = '';
if (pm.request.body.raw) {
    rawBody = pm.request.body.raw;
}

// 空body固定SHA256
const emptySha256 = '';
let bodySha256;

if (rawBody === '') {
    bodySha256 = emptySha256;
} else {
    bodySha256 = CryptoJS.SHA256(rawBody).toString(CryptoJS.enc.Hex).toLowerCase();
}

// console.log(
//     "httpMethod:"+httpMethod,
//     "path:"+path,
//     "queryString:"+queryString,
//     "bodySha256:"+bodySha256,
//     "timestamp:"+timestamp,
//     "nonce:"+nonce,
//     "appKey:"+appKey
// )

// ========== 5. 拼接 7 行待签名字符串 ==========
const canonical = [
    httpMethod,
    path,
    queryString,
    bodySha256,
    timestamp,
    nonce,
    appKey
].join('\n');

// ========== 6. HMAC-SHA256 签名（小写）==========
const sign = CryptoJS.HmacSHA256(canonical, appSecret).toString(CryptoJS.enc.Hex).toLowerCase();

pm.request.headers.upsert({
    key: 'X-SApi-App-Key',
    value: appKey
});
pm.request.headers.upsert({
    key: 'X-SApi-Timestamp',
    value: timestamp
});
pm.request.headers.upsert({
    key: 'X-SApi-Nonce',
    value: nonce
});
pm.request.headers.upsert({
    key: 'X-SApi-Sign',
    value: sign
});
```

## 常见问题

**Q：签名一直失败？**

- 核对 `PATH` 是否包含 `/sapi` 前缀且与真实请求一致。
- 核对 Query 是否按 key 排序编码。
- 核对 body 原始内容与 hash 是否一致（尤其 JSON 空格、字段顺序）。
- 确认 `app_secret` 无误且未混入首尾空格。

**Q：GET 用 Postman 的 JSON body 导致失败？**

- GET 不应带 body；若工具自动附加 `[]`，会导致 hash 与签名时不一致。

**Q：多环境如何配置时间窗口？**

- 在对应环境 `.env` 设置 `SAPI_TIMESTAMP_TOLERANCE`，单位秒。
