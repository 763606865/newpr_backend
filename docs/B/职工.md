# 职工

## 说明

职工接口对应 `\App\B\Controllers\EmployeeController`。
所有接口均基于当前登录企业进行操作（由后端根据当前 Token 自动识别企业）。

由于 `users` 表数据量较大，职工绑定用户采用“远程搜索”接口，不走全量下拉。

---

### 认证方式

请求头：

```http
Authorization: Bearer {access_token}
Accept: application/json
```

### 统一响应结构

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | int | HTTP 状态码（通常 `200`） |
| `data` | object\|array | 业务数据 |
| `meta` | object | 元信息 |
| `meta.timestamp` | float | 响应时间戳 |
| `meta.response_time` | float | 接口耗时（秒） |

---

## 职工列表

获取当前企业下职工列表，支持关键字和状态筛选。

### 请求详情

| 字段 | 值 |
|---|---|
| 方法 | `GET` |
| URI | `/b/employees` |

### 查询参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|
| `keyword` | string | 否 | - | 匹配姓名/手机号/邮箱/工号/关联用户信息 |
| `status` | int | 否 | - | `1` 在职，`0` 离职 |
| `per_page` | int | 否 | `20` | 每页数量，范围 `1-100` |

## 用户远程搜索

用于职工绑定 `users` 用户。该接口按关键词搜索，避免全量加载用户数据。

### 请求详情

| 字段 | 值 |
|---|---|
| 方法 | `GET` |
| URI | `/b/employees/search-users` |

### 查询参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|
| `keyword` | string | 否 | - | 搜索词（姓名/昵称/手机号/邮箱） |
| `per_page` | int | 否 | `20` | 每页数量，范围 `1-50` |

### 示例请求

```http
GET /b/employees/search-users?keyword=1660000&per_page=20
```

### 示例响应

```json
{
  "code": 200,
  "data": {
    "items": [
      {
        "id": 66,
        "name": "张三",
        "nickname": "",
        "phone": "16600000000",
        "email": "zhangsan@example.com",
        "avatar": ""
      }
    ],
    "meta": {
      "current_page": 1,
      "last_page": 1,
      "total": 1
    }
  },
  "meta": {
    "timestamp": 1777435057.215031,
    "response_time": 0.007
  }
}
```

## 创建职工

在当前企业下创建职工，并绑定 `users` 记录。

### 请求详情

| 字段 | 值 |
|---|---|
| 方法 | `POST` |
| URI | `/b/employees` |
| Content-Type | `application/json` |

### 请求体

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `user_id` | int | 是 | 关联用户 ID（来自远程搜索接口） |
| `department_id` | int | 否 | 部门 ID（必须属于当前企业） |
| `position_id` | int | 否 | 岗位 ID（必须属于当前企业） |
| `employee_no` | string | 否 | 员工工号；不传则自动生成 |
| `real_name` | string | 否 | 员工姓名；为空时回填用户姓名 |
| `avatar` | string | 否 | 头像地址；为空时回填用户头像 |
| `email` | string | 否 | 邮箱；为空时回填用户邮箱 |
| `mobile` | string | 否 | 手机号；为空时回填用户手机号 |
| `status` | int | 否 | `1` 在职，`0` 离职，默认 `1` |
| `entry_time` | string | 否 | 入职时间（日期时间格式） |

### 示例请求

```json
{
  "user_id": 66,
  "department_id": 3,
  "position_id": 5,
  "employee_no": "",
  "real_name": "",
  "status": 1,
  "entry_time": "2026-05-19 10:00:00"
}
```

### 示例响应

```json
{
  "code": 200,
  "data": {
    "id": 9,
    "company_id": 12,
    "user_id": 66,
    "department_id": 3,
    "position_id": 5,
    "employee_no": "EMP202605191530110001",
    "real_name": "张三",
    "mobile": "16600000000",
    "email": "zhangsan@example.com",
    "status": 1,
    "user": {
      "id": 66,
      "name": "张三",
      "phone": "16600000000"
    }
  },
  "meta": {
    "timestamp": 1777435057.215031,
    "response_time": 0.012
  }
}
```

|---|---|---|---|

### 成功响应示例

```json
{

  "data": [],
  "meta": {
    "timestamp": 1777435057.215031,
    "response_time": 0.003
  }

```

---

## 校验规则补充

- `user_id` 在同一企业内只能绑定一次（忽略软删除数据）。
- `department_id`、`position_id` 必须属于当前企业。
- `employee_no` 在同一企业内唯一（忽略软删除数据）。
