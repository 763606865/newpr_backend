# 联系我们

面向 C 端游客的公开咨询上报接口。提交成功后，数据进入运营后台“联系申请”列表，由运营人员进行回访和记录跟进备注。

---

## 1) 提交联系申请

- 接口：`POST /cms/contact-inquiries`
- 路由名称：`contact-inquiry.store`
- 鉴权：无
- Content-Type：`application/json`
- 限流：同一限流标识每分钟最多 `5` 次

### 请求参数

| 字段 | 是否必填 | 类型 | 规则 | 说明 |
|------|----------|------|------|------|
| `name` | 是 | string | 2～50 个字符 | 姓名或称呼 |
| `phone` | 是 | string | 中国大陆 11 位手机号 | 用于运营人员回访 |
| `company_name` | 否 | string\|null | 最大 150 个字符 | 公司名称 |
| `source` | 否 | string\|null | 最大 100 个字符 | 信息来源，例如 `website`、`mini_program`、`app` |
| `product` | 是 | integer | 取值见咨询产品枚举 | 咨询的产品或服务 |
| `content` | 是 | string | 10～5000 个字符 | 申请或咨询内容 |

### 咨询产品枚举

| `product` | 含义 |
|-----------|------|
| `1` | 招聘服务 |
| `2` | 校园招聘 |
| `3` | 人才服务 |
| `99` | 其他 |

### 请求示例

```http
POST /cms/contact-inquiries
Content-Type: application/json
Accept: application/json
```

```json
{
  "name": "张先生",
  "phone": "13800138000",
  "company_name": "示例科技有限公司",
  "source": "website",
  "product": 1,
  "content": "希望了解企业招聘服务和相关套餐，请与我联系。"
}
```

### 成功响应

HTTP 状态码：`200`

```json
{
  "code": 200,
  "data": {
    "id": 1001,
    "status": 0,
    "submitted_at": "2026-07-31 11:30:00"
  },
  "meta": {
    "timestamp": 1785468600.1234,
    "response_time": 0.0123
  }
}
```

### 响应字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `code` | integer | 业务状态码，成功为 `200` |
| `data.id` | integer | 联系申请 ID |
| `data.status` | integer | 回访状态；新申请固定为 `0`（待回访） |
| `data.submitted_at` | string | 服务端记录的申请时间，格式 `Y-m-d H:i:s` |
| `meta.timestamp` | number | 响应生成时间戳 |
| `meta.response_time` | number | 接口响应耗时，单位秒 |

### 验证失败响应

HTTP 状态码：`422`

```json
{
  "message": "手机号 字段格式无效。 (and 1 more error)",
  "errors": {
    "phone": [
      "手机号 字段格式无效。"
    ],
    "content": [
      "申请内容 字段必须至少有 10 个字符。"
    ]
  }
}
```

可能出现验证错误的字段：`name`、`phone`、`company_name`、`source`、`product`、`content`。

### 请求过于频繁

超过每分钟 5 次限制时返回 HTTP `429 Too Many Requests`。前端应提示用户稍后重试，避免立即循环提交。

---

## 服务端处理规则

- `status` 由服务端强制设置为 `0`（待回访），忽略客户端自行传入的状态。
- `submitted_at` 由服务端生成，不接受客户端传入。
- 服务端自动记录请求 IP 和最长 500 字符的 User-Agent，但这些字段不会在提交响应中返回。
- `company_name` 和 `source` 可不传，也可传 `null`。
- 当前接口不进行手机号验证码校验，也不自动合并或覆盖历史申请。
- 同一个手机号可以提交多条咨询，限流只用于抑制短时间高频请求。

## 前端接入建议

1. 提交按钮点击后立即进入 loading 状态，成功或失败后再恢复，防止重复点击。
2. `source` 使用稳定的机器可读值，例如 `website_contact`、`mini_program_contact`、`app_contact`。
3. 收到 `code = 200` 后展示“提交成功，我们会尽快与您联系”，无需继续轮询申请状态。
4. 收到 `422` 时按 `errors` 字段展示对应表单错误。
5. 收到 `429` 时提示“提交过于频繁，请稍后再试”。
